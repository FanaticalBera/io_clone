Node **24.21.0** 기준입니다. 이 작업 환경에는 공식 SHA256을 확인한 런타임이 `.tools/node-v24.21.0-win-x64`에 있습니다. 다른 PC에서는 Node 24를 설치하세요.

```powershell
cd "C:\Users\Home Bsw\Desktop\sixio_clone"
$env:PATH = "$PWD\.tools\node-v24.21.0-win-x64;$env:PATH"
npm ci
npm run build
npm start
```

[PC 게임](http://localhost:3001). 서버가 빌드된 웹과 Socket.IO를 같은 주소에서 제공합니다. 종료는 실행한 터미널에서 Ctrl+C입니다. 실행 중인 Vite/tsx/esbuild가 파일을 사용하면 Windows의 npm ci가 EPERM으로 실패할 수 있습니다. 해당 작업을 종료한 뒤 재설치하세요.

개발: `npm run dev` → [웹 5173](http://localhost:5173), 서버 3001. 각각 `dev:client`, `dev:server`도 가능합니다. Vite는 /socket.io의 polling·WebSocket을 proxy합니다. 클라이언트만 실행해도 로드된 봇 연습은 서버 없이 진행됩니다.

## LAN / PC 핫스팟

PC는 랜선, 폰은 PC의 모바일 핫스팟에 연결해도 됩니다. 폰에서 localhost를 사용하면 폰 자신을 가리키므로 **PC 핫스팟 주소**로 여세요.

현재 사용자 구성은 Galaxy S24+ / Android 15, PC 핫스팟 주소 `192.168.137.1`입니다. 실기기 테스트용 서버는 핫스팟 인터페이스의 3003 포트에서 실행합니다.

```powershell
$env:HOST = "192.168.137.1"
$env:PORT = "3003"
npm start
```

폰/PC 주소: [핫스팟 게임 + FPS](http://192.168.137.1:3003/?metrics=1). `metrics=1`은 최근 30초 평균 FPS·가장 느린 1% 프레임의 FPS·온라인 RTT를 표시하며 게임 판정을 바꾸지 않습니다. 수정 후 기존 탭은 새로고침하고 PC에서 오래된 화면이 보이면 Ctrl+F5를 사용하세요. 다른 네트워크에서는 실제 PC 주소를 확인해서 사용하세요. 외부망 접속에는 별도 접근 가능한 서버/HTTPS 주소가 필요합니다.

시간 초과가 발생하면 폰의 Wi-Fi IP/게이트웨이, 서버 실행 상태, Windows 방화벽을 확인합니다. `scripts/allow-hotspot.ps1`은 관리자 권한으로 이 프로젝트의 Node·TCP 3003·로컬 192.168.137.1·원격 192.168.137.0/24만 허용합니다. 기존 Node Block 규칙이 Allow보다 우선하면 관리자 audit으로 먼저 확인하세요. 이번 테스트에서는 해당 규칙을 백업한 뒤 3003만 제외했습니다. `scripts/remove-hotspot.ps1`은 기존 차단 규칙을 복원하고 테스트 Allow를 제거합니다. helper의 규칙 ID는 이 PC에서 검증한 값이므로 다른 PC에 그대로 적용하지 마세요. 방화벽 전체를 끄지 않습니다.

## 환경 변수

| 변수 | 기본 | 의미 |
|---|---|---|
| PORT | 3001 | HTTP·Socket.IO 공통 포트 |
| HOST | 0.0.0.0 | 수신 주소; 특정 핫스팟 IP로 제한 가능 |
| MAX_ROOMS | 10 | 신규 방 생성 상한, 성능 보장치 아님 |
| ALLOWED_ORIGINS | 빈 값 | 같은 Host의 Origin 허용; 추가 Origin은 쉼표로 구분 |

개발 TS 진입점은 localhost/127.0.0.1:5173도 허용합니다. 운영 진입점은 명시한 Origin과 같은 Host만 허용합니다. Origin이 없는 Node 테스트 클라이언트는 허용합니다. proxy 신뢰/X-Forwarded-For는 켜지 않습니다.

`/healthz`는 활성 방·연결 수를 반환합니다. SIGINT/SIGTERM 종료 시 새 방을 막고 중단 안내 후 루프·연결·세션을 정리합니다. 세션은 서버 프로세스 메모리만 사용하므로 재시작한 경기는 복구하지 않습니다.

## 구조·범위

`src/shared`: 설정, 육각 좌표·연속 이동, 소유권·선, BFS 점령, 동시 사건, 생명/등장, 점수, 봇, 프로토콜. `src/server`: Express·Socket.IO·세션·방·입력 권한·루프·상한. `src/client`: Phaser 표시, HTML UI, 공통 입력, 연습/온라인, 표시 예측.

모드 설정·평가는 src/shared/modes.ts에서 관리합니다. createMode()는 Classic 설정만 만들며, 서버는 이전 HOLD 모드 요청을 거부합니다. Classic 승패는 100% 점령으로만 판정하며 메뉴의 모드 전환과 경기 중 모드·목표 표시창은 제거했습니다.

PRD/TECH는 `docs/`에 유지하며 현재 규칙·환경설정·모바일 조작·진동·점령에 의한 연결 절단·전장 축소를 v0.5에 반영했습니다. 원래 작업 계획은 `docs/TASKS.original.md`에 보존했습니다. 문서 작성 당시의 ‘계획만 작성’ 지시와 현재 구현 요청을 구분했습니다.

공개 배포/HTTPS 운영, APK/Capacitor, 계정·영구 랭킹, F01~F06은 이 작업에 포함하지 않았습니다. Phaser 번들은 약 1.3MB(압축 약 357KB)이며, 실기기/대역폭 결과는 VERIFICATION에 구분해 기록합니다.

사망 영토 연출 V1은 [사양](docs/territory-death-effects-plan.md)과 [측정·검증 보고서](docs/territory-death-effects-results.md)에 기록했다. 사용자 최종 선택에 따라 사망 연출의 운영 기본값은 WAVE_COLLAPSE다. development/test에서는 experimentTerritoryEffect=wave|power|edge로 비교한다. 같은 장면의 50/250/1,000칸 비교 화면은 /tests/fixtures/territory-effects.html이고, 화면 아래 링크로 실제 R56/16 봇 연습을 열 수 있다. 전용 검사는 npm run test:territory-effects를 사용한다.

플레이 피드백을 반영해 Capture를 240ms 동시 강조·외곽선(Pulse)으로 바꿨다. 사망뿐 아니라 관측된 탈취로 중립화된 생존 상대의 고립 영토도 Wave로 연출한다. [현재 구현·검증 결과](docs/capture-effect-v1-results.md)를 참고한다. Capture 운영 기본값은 Pulse ON이다. 별도 URL 옵션 없이 동작하며 development/test에서 experimentCaptureEffect=none으로 끌 수 있다. 기존 bloom 링크도 새 효과를 사용한다. fixture의 상대 영토 탈취 재생 버튼으로 두 경우를 함께 확인할 수 있다.

## Run 보상과 로컬 프로필 V1

Coins와 Run 통계는 IndexedDB에 저장한다. 시작 영토 그대로 무처치 종료한 Run은 0 Coins이며, 진행한 Run은 기본 5 + 최고 점유율 × 2(내림) + 처치당 3(최대 10처치) + Classic 클리어 100으로 계산한다. 최근 상세 내역 256개와 현재 월드의 lifeId 지급 기록을 따로 관리해 중복 지급을 막는다. 저장 실패 시 결과창에서 저장 재시도를 제공한다. 서버·게임 상태·RunResult에는 보상 데이터를 넣지 않는다.
