## 3. 1순위 — PERIMETER_GUARD 계획 중단

**질문:** 실제 실행 중인 확장이 벽 때문에 필요한 중단인지, 경계에서 회전하지 못할 경로가 먼저 선택된 것인지, 동일 상황 재선택이 반복되는지 분리한다. ‘벽 회피를 줄이면 성장한다’를 결론으로 전제하지 않는다.

분석 단위는 (seed·참가자·life·실제 새 계획 순번)이다. 선택 후 입력 출력 전에 버린 계획, 실제 채택 후 외부 진입 전 취소, 외부 선 노출 중 취소를 나누고 완료·귀환·새 계획 교체·사망에서 episode를 닫는다. PLAN_CONTINUE의 반복 메타데이터와 같은 guard 통지를 새 중단으로 중복 계산하지 않는다. 창 끝 미완료는 censored다.

기록할 항목은 선택 출발점·shape·길이·중립/탈취 예상 칸·D 가산·당시 벽 거리, 실제 position/heading/조향, guard의 0.65초 swept 첫 벽 접촉 예측, 원래 계획의 선 유무/귀환 지점, 교체 방향이다. 현재 실제 벽 look-ahead·회전율·이동 엔진을 그대로 재사용해 왜 차단됐는지만 설명한다.

중단 후 2초를 관측해 선의 회수·실제 점령·사망 원인·확장 재개·같은 출발점/같은 방향 재취소를 보고한다. 사망/생명 변경/창 끝에서 이후 관측을 자르고 완전 2초 표본 수도 표시한다. 중단 계획의 예상 점령은 실제 잃은 칸으로 계산하지 않으며, 실제 점령/보유 감소의 인과 효과는 수정 전에는 알 수 없다고 적는다.

분모는 실제 채택 확장 수·벽 근처 확장 수·생존 봇분을 함께 제시한다. 성격·시드·벽 거리군(0~1/2~3/4칸 이상)·선0/노출 선·D 유무별로 중단율과 정상 완료율을 비교한다. 시드19/137의 빈도가 높은 장면을 case ID 기준으로 선택하되, 원본 중단 목록을 먼저 고정하고 유리한 장면만 뽑지 않는다.

산출물은 계측 분모 검증, 원인 분포, 반복 재선택/귀환 실패 사례, 성격별 완료/보유 관계, 후속 수정의 필요성이다. 경로 선택의 병목이라면 후속안은 안전한 후보 생성/선택 쪽을 검토한다. PERIMETER_GUARD의 예측 시간·벽 임계·회피를 완화하는 안은 이번 분석/구현 범위가 아니다.

## 4. 2순위 — 보유 시간 평균 성장 정체

벽 중단 분석과 같은 재생에서 BotHoldingTracker로 매 tick 처리 후 실제 보유를 수집한다. 죽은 시간0칸·부활 지급을 그대로 포함하고 사망 중립화 손실을 되더하지 않는다. 봇별·성격별·시드별 보유 시간 평균, 최종 보유, 최대 점유율과 생존 시간/사망 원인을 보고한다.

평균치만 비교하지 않고 사전 고정30초 창(t1~900/901~1800/1801~2700/2701~3600)별로 본다. 사망 대기/리스폰, 자기 땅 이동/재배치, 노출 확장, 귀환/안전 대응, 공격을 배타적 활동 분류로 구분하며 활동이 곧 원인이라고 단정하지 않는다. 생존 중 보유 변화와 사망으로 줄어든 보유를 분리하여 ‘확장 실패’와 ‘많이 죽어서 땅을 잃음’을 구별한다.

활동 분류의 우선순위는 사망 대기 → ATTACK → RETURN/ESCAPE → REPOSITION → 노출된 EXPAND/STEAL → 자기 땅 이동/기타다. 각 tick은 한 범주에만 넣는다. 이 분류는 행동을 재선택하는 규칙이 아니라 관측 통계의 분모다.

실제 점령 transfer로 중립 칸 획득·타인 영토 탈취·타인에게 뺏김·사망 중립화·부활 지급을 회계상 구분한다. 실제 피해 되찾기는 획득의 부분집합이고 중립화 피해 회수는 별도라 중복 합산하지 않는다. 예상 영토 증가/루프 규모와 실제 완료율/수익을 비교하여 출발점 부족·위험 취소·귀환 시간·크기/모양·영토 손실 중 어디서 성장이 정체되는지 좁힌다. 개인별 전략 재도입·새 가산점·큰 루프 허용은 이 단계에서 하지 않는다.

산출물은 성장 정체의 유형과 성격별 분포, 벽 중단과의 관계, 다음에 한 가지만 수정한다면 어디인지다. b의 중단 횟수 전체를 가상의 점령 손실로 더하지 않는다. 보유 주 지표와 자연 대전 사망·되찾기·성격·공격·비용의 기존 재검토 기준을 후속 수정 평가에 유지한다.

## 5. 3순위 — NO_APPROACH 거절 분해

현재 수치46,862회(전체 거절 관측의64.88%)는 후보 평가 관측 수이며 독립 공격 기회 수가 아니다. 전술100ms로 같은 선을 더 자주 평가하므로 총수만으로 우선 수정하지 않는다. 동일 판단의 중복 후보를 제거한 기존 정의와, 같은 상대/생명의 연속 관측 선 구간 단위도 함께 보고한다. 단일 후보가 NO_APPROACH라고 전체 선 구간에 공격 경로가 없었다고 표시하지 않는다.

NO_APPROACH는 현재 거리 상한L과 관측 머리1초 예측 칸H를 동시에 적용한 shortestPath 실패다. native 판정을 먼저 기록한 뒤 읽기 전용으로 세 BFS를 추가한다: **①L유지/H만 제외 ②L상한만 제외/H유지 ③둘 다 제외**. native의 target 칸 예외·맵·시작 칸·목표 칸·인접 관계는 같고, 상한 없는 진단의 최대는 맵 칸 수−1로 도달성만 본다.

진단 경로가 있어도 공격 허용으로 세지 않는다. 최소 접근 길이·상한 초과량·예측 머리와 겹치는 칸·노출 시간을 보고하고 귀환/선 예산/역절단/ETA 검사를 전부 통과한 기회라고 표현하지 않는다. 다른 거절인 TRAIL_BUDGET/VICTIM_RETURNS_FIRST와 같은 reason으로 합치지 않는다. 원래 범위 밖 머리를 추가하거나 미래 입력을 사용하지 않는다.

성격별(특히 선사냥꾼/영역도둑), 거리군, 전술/전략 층, 실제 선 구간별 반복 지속 시간을 보고한다. 확장 audit와 자연8시드에서 어느 유형이 실제 미응징과 함께 나오는지 확인한 뒤에만 후속 접근 개선안을 제안한다. 거리 상한·머리 회피·공격 확률 수정은 이 계획에 포함하지 않는다.

## 6. 완료·승인 경계

각 묶음은 읽기 전용 계측의 해시 동일성 → 기준 분포/대표 사례 → 판단 가능한 결론/불확실성 → 단일 수정 필요 여부 순서로 보고한다. 행동 수정은 별도 사용자 승인 전까지 하지 않는다. 비용 성능은 진단 observer 없는 코드로 측정하고 계측 자체의 추가 비용과 혼동하지 않는다. 모든 후속 합격 보고의 기존16개와 known seed1 검사는 유지한다.

위는 최초 계획 당시 상태다. 2026-10-13 벽 선택 전 검사 구현과 사람 플레이 확인 후 이를 유지하고, 성장 분석을1순위로 정했다. [성장 분석과 단일 제안](bot-ai-phase04-growth-analysis.md)을8시드·4분으로 완료했다. 보유64칸 이상·관측 머리0명일 때 기존 후보를 보존하며 큰 변형을 추가하는 안은 승인 전이다. prefix 이동 중 중단417건·벽병렬경로는 후속 후보로만 보존한다. NO_APPROACH의12칸 관측 선 절단0과선사냥꾼15.6%<탐험가16.8% 질문은 성장 뒤에 다룬다. master와 원격은 그대로 둔다.
