# 확장 공격 audit 제안 — 고정 조건에서 실제 선 절단 성공률

2026-10-13 · 프로토콜 제안만 완료 · 실행/평가 코드와 행동 수정은 승인 후

**2026-10-13 후속 승인·실행 완료:** 기존8배치는 근거리 비중이 낮아 교체했다. R22 스폰에서는7·9칸을 matchSeed로 만들 수 없어 사용자 승인으로5칸4배치·12칸3배치·17칸1배치를 고정했다. 선정은 초기 거리/배치 중복/최소seed만으로 했고 결과 전에 프로토콜에 기록했다. 최신 [확장 기준 측정](bot-expanded-attack-baseline.md)은155/1024,기존16개는13/16이다. 아래8개 원래seed 제안과 미실행 표시는 당시 기록이며 최신v2가 우선한다.

기존16개는 그대로 유지한다. 현재13/16에서 실패ID5·6·14는 **출발 안전의 알려진 대가**로 기록하고 이번4단계의 복구 목표에서 제외한다. 기존 성공13개 중 새 손실이 없어야 하며, 이후 승인 버전에서 추가 회복한 사례도 다음 기준에 포함한다. departure-response1안·2안과t7 추가 분석은 종료한다. 원래memorySeed1 기대 실패는 별도 알려진 회귀로 보존하며 출발 안전의 세 실패와 같은 원인으로 합치지 않는다.

확장 검사는 특정 배치·성공하는 memorySeed에 의존하지 않고 실제 절단 결과를 비교하기 위한 별도 지표다. 실패 사례를 뺀다거나 성공 시드를 찾아 기존16개를 바꾸지 않는다.

## 1. 고정 행렬 제안

**8스폰 배치 × memorySeed8개 × 성격4개 × 기존 사람 루프4개 = 1,024케이스**다. 행동 기준은 승인된3단계133ee1f다. 현재 실험 브랜치의 이후 변경은 문서/읽기 전용 계측뿐이며 shared 행동은 동일하다. 실행 전에 해당 커밋의 소스·프로토콜을 동결하고 이후 버전도 같은 케이스를 비교한다.

## 2. 성공률과 실패 분류

**주 지표 = 해당 봇에게 귀속된 실제 선 절단 성공 케이스 수 / 고정1,024케이스 수.** 한 케이스는 최대1성공이다. 사람 DEATH의 killerId가 해당 봇이고 cause가 EXISTING_TRAIL_CONTACT/PENDING_TRAIL_CONTACT여야 한다. HOME_CAPTURE·벽 사망·다른 원인의 처치는 성공에 포함하지 않는다. 성공 시 봇 생명·동시 사망도 별도로 기록하여 리스폰 후 처치나 교환 사망을 숨기지 않는다.

공격을 시작한 케이스만 분모로 삼지 않는다. 미관측·미시도·도달 실패·안전 거절·루프 완료/시간 종료도0으로 남는다. 경기/초기화 오류는 성공/실패로 바꾸지 않고 전체 실행 미완료로 보고한다. 인간 혼자 같은 입력을 따랐을 때의 루프 물리 검증을 먼저 진행하고, 이상이 있으면1,024개 프로토콜을 완성된 것으로 선언하지 않는다. 봇 버전의 결과를 보고 불리한 케이스를 사후 제외하지 않는다.

계측은 다음을 함께 제공한다.

- **케이스 성공률:** 전체, 배치별, 거리군별, 성격별, memorySeed별, 루프별. 모든 분자/분모를 표기한다.
- **의도된 공격 구별:** 실제 절단 중 최종 ATTACK이 선택한 사람/생명을 노린 동안 발생한 절단과 확장/순찰 중 우연한 절단을 구별한다. 주 지표의 기존 실제 절단 정의를 몰래 변경하지 않는다.
- **공격 과정:** 공격 시작·선택 표적 처치·자기 사망/원인, 공격 도착tick, 사람 최대 노출 선, 관측된 사람 선의 존재 여부/시간, 루프 점령·완료/timeout.
- **실패 이유:** 관측된 선 없음, 후보 없음, 기록된 거절 사유별, ATTACK 선택 후 실패/중단, 자기 사망. 마지막tick의 거절 하나를 케이스 전체의 유일한 원인으로 단정하지 않으며 판단 횟수와 노출 구간 단위 분포를 나눈다.

‘관측된 선이 있었던 케이스의 성공률’과‘공격 시작 후 성공률’은 **보조 진단**으로만 제공한다. 봇 버전의 움직임에 따라 이 분모가 달라지므로 고정 케이스 성공률 대신 비교하지 않는다.1,024개는 독립 표본1,024판으로 일반화하지 않는다. 같은 배치/루프를 공유하는 행렬이다.

## 3. 전후 비교와 채택 보고

확장 기준 수치는 아직 측정하지 않았다. 현재 버전으로 먼저1,024개 기준을 동결한 뒤 변경 버전을 같은 케이스ID로 짝 비교한다. 전체 성공률 변화와 성공→실패/실패→성공의 케이스 목록, 배치8개별 변화, memorySeed/성격/루프별 분포를 보고한다. 배치별 방향 수와 배치 하나를 뺀 변화도 함께 보며, 케이스 수가 많다는 이유만으로 기존8시드 방향 기준을1,024개 독립 표본에 적용하지 않는다. 새로운 절대 성공률 목표는 기준 측정 전에 임의로 정하지 않는다.

모든 단계 보고에서 **기존16개13/16·기존 성공 케이스 새 손실0**을 별도 필수로 유지한다. 확장 성공률이 올라도 기존13개를 하나 잃으면 상쇄된 것으로 처리하지 않는다. 자연 대전8시드의 보유 시간 평균·사망·공격 시작/표적 처치·성격별 탈취/TV·비용도 기존 방식으로 같이 검토한다. 출발 안전의 사망 감소와 벽 사망0을 성장/공격 이득과 바꾸지 않는다.

같은 케이스의observer ON/OFF 궤적·판단·메모리·다음 RNG·예약 동일성을 확인한다. 최소 정합성 표본은 기존16개와 나머지 배치 각 성격1케이스(28개) 등 총44개를 사전 고정한다. 서로 같은 케이스를 중복 세지 않는다. 실행 자료는 source/protocol 해시와 케이스별CSV를 남기고 전체frame/trace는.local에 보존한다. 실험 실패나 불완전 결과를 통과 보고서로 만들지 않는다.

## 4. 구현 전 제안하는 실행 순서

프로토콜 승인 → 인간 루프 물리 검증/정적 행렬 확정 → 현재 기준1,024개 측정·observer 정합성 → 기준 보고 순서다. 이 audit은 아래4단계 분석의 공격 부작용 검증 도구이며, 출발 차단 응징이나t7 방향 수정의 재개가 아니다. 아직 평가 실행 코드는 구현하지 않았다.

[제안 프로토콜·정적 검증](../evidence/bot-phase04-plan/expanded-audit-protocol.json)에 축·스폰 좌표·고정 케이스ID 해시를 보존했다. 초기 스폰/경유점 검증은 완료했고 인간 루프의 실제 이동·공격 성공률은 미측정이다.
