# 3B 구현·8시드 비교, 3C 사전 측정, 3D prefix 계측

2026-10-12 · 실험 브랜치 codex/bot-ai-phase01 · 구현 7ebf4eb · 기준 5b714ea(3A, c84fc7a 행동과 동일) · master 960f678 유지

사용자 승인에 따라 **3B 전술 100ms·개인별 전략 주기**를 적용했다. 3C 연속성 가산점과 집요함 배정은 켜지 않고 기준 재생에서 두 식의 선택 변경 가능성만 측정했다. 3D는 기존 출발 경계까지의 자기 땅 prefix를 관측했다. 추가 대기·새 재배치·근접 계획 점수 변경은 없다. [근접 계획 선택 제안서](bot-ai-near-plan-proposal.md)는 승인 전이며 별도 구현하지 않았다.

## 3B 적용 내용

|성격/층|정규 주기(30Hz)|
|---|---|
|즉시 안전|기존대로 매 tick / 33.3ms|
|전술 안전|3tick / 100ms, 선 노출 또는 ATTACK/RETURN/ESCAPE/REPOSITION|
|선사냥꾼 전략|5~8tick / 166.7~266.7ms|
|영역탐험가 전략|6~10tick / 200~333.3ms|
|안전지킴이 전략|4~7tick / 133.3~233.3ms|
|영역도둑 전략|5~9tick / 166.7~300ms|

주기와 시작 위상은 botSeed에서 도메인 0x6c5e9d13으로 분리한 RNG로 한 번 뽑는다. 행동·특성·성격·닉네임·예약 RNG를 배정 때문에 소비하지 않는다. 부활은 개인 프로필을 유지하고 판단 기한을 초기화한다. 전략이 먼저 오면 전술도 함께 계산한다. 자기 땅으로 돌아와 전술 처리에서 경로가 완료/무효화된 경우는 전략을 즉시 다시 선택할 수 있고, 생명/벽 회피 등 기존 긴급 재판단도 유지한다. 정규 주기를 최소 계획 유지 시간이라고 해석하지 않는다.

전술만 도래한 tick에도 실제 선택 순서를 예약 RNG로 셔플하고 일반 공격 예약을 즉시 등록/갱신한다. 다른 봇은 같은 tick 앞 예약을 본다. 생존 역공으로 일반 공격을 우회하지 않는다. 공통 루프를 쓰는 연습·관전·LAN·온라인에 같은 구현이 적용된다. 사람의 background returnOnly 및 baseline/fairness/cache/phase 비교 갈래는 기존 공통 주기를 유지한다. combined만 3B를 채택해 역사적 비교 갈래의 뜻을 바꾸지 않았다.

기존 출발/재배치 시작 안전은 매 tick 그대로이며 위험·선 길이·귀환·근접 머리 조건, V=0, D 상한 +6, 성격별 6개 경계 뒤 피해 경계 최대 2개 추가, 재배치 봇 전체 6초 대기와 예약 상한 3은 변경하지 않았다. 공개 생명·대상 선 소멸 시 예약 해제는 매 tick이고 전술 계획 유효성 재평가는 해당 전술 tick에 수행한다. HUD에 개인 전략 주기와 다음 전략·전술 tick을 표시한다.

## 3C: 기준 궤적에서 C가 선택을 바꿀 횟수

기준은 3B를 켜기 전의 3A 재생이다. 집요함을 배정하지 않고 각 봇의 한 판단에서만 C를 가정해 기존 후보를 다시 정렬한다. 다른 봇·특성·궤적·과거 완료 이력은 기준 상태 그대로다. 따라서 **모든 봇에 대한 잠재 기회 수**이며 실제 집요함 배정 후 발생 횟수나 후속 생존/성장 효과 예측이 아니다. 적용 범위는 다음 일반 전략 후보 선택이며 생존 역공·긴급 interrupt 공격·현재 계획 강제 유지에는 C를 넣지 않는다.

완료한 유효 계획의 같은 피해 구역(출발 경계 거리 3칸 이내, 현재 D>0) 또는 같은 공격 상대 ID+생명을 6초간 기억한다. 안전 취소를 완료로 저장하지 않는다. 실제 사망/귀환 완료와 현재 생명·대상 생명·관측 가능한 후보를 사용한다. 기존 공격 허용/귀환/위험/예약/출발 안전을 통과한 후보만 재평가하고 기존 동점 열거 순서를 유지한다.

|식|확장 점수 증가|
|---|---|
|현재안 C1|C1=min(1, 0.10×max(0, 기본 점수)); 증가=min(6, 0.50×max(0, 기본 점수), D raw+C1)−현재 적용 D|
|대안 C2|C2=min(2, 0.10×max(0, 기본 점수)); 현재 적용 D에 C2를 별도로 추가|

대안도 기본 점수의 10% 제한을 유지한다. 별도 상한은 총 D+C가 최대 +8까지 갈 수 있음을 뜻하며 런타임 D 상한을 바꾼 것은 아니다. 공격은 예약 배율 전 점수에 C를 더하고 같은 배율을 적용한다. V=0은 두 안 모두 유지한다.

별도 상한의 추가 변화는 3회(시드 4·19·11 각각 1회)이고 나머지 5시드는 동률이다. 두 안의 체감 효과 차이는 구분 불가다. 선택을 더 바꿨다는 것 자체를 좋은 변화로 부르지 않는다. **이번 결과만으로 C2나 집요함 활성화를 추천하지 않는다.** 근접 계획 선택 문제와 분리해 3C의 도입 여부를 다시 검토한다. 성격별 기회 수 및 변경 장면 seed/slot/tick은 증거 CSV에 있다.

## 3D: 기존 prefix 실제 이동 계측

새 계획의 처음 연속된 자기 소유 경로 노드를 prefix로 정의하되, 시간은 실제 소유 칸이고 선이 0인 프레임만 센다. 목표 경계에 물리적으로 도착하면 ARRIVED, 도착 전 실제 노출이 생기면 EXPOSED_BEFORE_TARGET으로 구분한다. 소유 경로 노드가 안전한 실제 턴 궤적을 보장한다고 가정하지 않는다. 출발 차단·벽 회피·계획 교체·소유권 상실·생명 변경·측정 종료도 별도로 기록한다. 관측 종료 CENSORED는 도착/실패로 합치지 않는다.

## 검증과 비용

- 전체 Vitest 95파일·662개 통과, 프로젝트 client/server/tests 타입 검사 및 변경 audit/performance 스크립트 strict 검사 통과.
- 클라이언트 production·서버 빌드는 로컬 산출 경로로 성공했다. 기존 번들 크기 경고는 그대로다. PC 관전/HUD/카메라/production 비노출 Playwright 9개 통과.
- 기준에 후보 계측을 추가한 8시드가 3A/c84fc7a와 궤적·판단·메모리·다음 RNG 값 모두 같다. 현재의 후보/prefix observer ON/OFF도 8시드 모두 동일하다. HUD ON/OFF는 실제 부활을 포함한 900tick 테스트에서 메모리 전체·입력·경기·예약 및 RNG를 비교했다.
- 전술 단독 귀환·일반 공격 예약 등록/갱신·최대 추격 3명, 개인 주기 범위/분리 RNG/부활 프로필 유지와 C의 상한/대상 ID/생명/만료 및 prefix 실제 노출을 검증했다.
- 주기 변경으로 특정 장면의 tick은 달라진다. 기존 조기 폐쇄의 고정 기하 증인은 combined 규칙을 유지한 채 스케줄 프로필만 비워 옛 6tick 주기에 고정했다. 공격 증인은 같은 실제 스폰/사람 루프에서 Hunter seed15·Thief seed8을 사용하며 양쪽 슬롯 역할·실제 절단·선 크기·귀환 조건을 그대로 검사했다. 판단 사이 안전 증인은 두 층의 기한을 모두 미래로 지정했다. 기존 안전/성공 조건을 완화하지 않았다.

## 다음 검토와 관전

3B 구현과 요청한 계측은 완료했다. 성장/사망/비용 한도와 벽 사망·예약·비간섭을 확인하되, 되찾기 감소·성격 차이 축소·근접 교체 증가를 함께 보고 **3C/근접 점수 구현은 승인 전 보류**한다. 개선 효과가 확인됐다고 자동으로 다음 단계로 넘어가지 않는다.

우선 영역도둑과 영역탐험가를 같은 seed에서 본다. 둘 다 선택지가 있는 중립/상대 국경에서 탈취와 중립 확장의 우선순위가 남는지 확인한다. 안전지킴이는 안전 귀환 뒤 다시 정상 확장을 시작하는지, 같은 출발을 막혔다가 반복하는지 본다. 선사냥꾼은 전술 공격 기회/예약 회귀를 짧게 확인한다. 개별 사망을 이유로 새 안전 조건을 계속 추가하지 않는다. 이전 t6787 등 고정 장면이 새 주기에서 동일 tick에 나올 것으로 가정하지 않는다.

원본 재생·prefix·후보 예시·고정 소스·성능 표본·로그는 기본 저장소 .local/bot-phase03b/에 보존한다. 저장소에는 [요약 JSON](../evidence/bot-phase03b/summary.json), [시드별 차이 CSV](../evidence/bot-phase03b/paired-seeds.csv), [C 봇별 집계](../evidence/bot-phase03b/continuity-bots.csv), [C 변경 장면](../evidence/bot-phase03b/continuity-examples.csv)과 검증 요약만 둔다. master는 변경하지 않았고 반영은 3단계 완료 후다.
