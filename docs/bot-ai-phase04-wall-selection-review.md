# 4단계: 확장 선택 전 벽 검사 결과

2026-10-13. 사용자 승인 범위 한 가지를 구현했다. 현재 판정은 **자동 회귀 확인 완료, 실제 사람 플레이 대기**다. 성장이나 생존이 개선됐다고 채택을 확정하지 않는다. master와 원격은 변경하지 않는다.

기준은 승인된 전술 100ms의 `133ee1f`다. 후보는 실험 브랜치 `269c8c1`에서 작업한 shared 소스를 동결했다. 실제 코드 차이는 `bot-strategy.ts`와 `bot-immediate-safety.ts` 두 파일이며, 전체 파일 SHA256을 요약에 보존했다. archive와 작업 폴더 사이의 다른 두 파일 차이는 CRLF/LF뿐임을 정규화 후 확인했다.

## 변경 범위

점수순 후보에서 기존 출발 안전 검사를 통과한 뒤, EXPAND/STEAL에만 `expansionPerimeterBlocked`를 적용한다. 현재 셀이 기존 radius−2 벽 띠 안일 때 복사한 경로의 waypoint를 기존 reach 기준으로 소비하고 실제 첫 조향을 구한다. 기존 `perimeterEscapeDirection`이 그 조향을 바꿀 후보만 건너뛴다. 다음 기존 후보를 선택하며, 없으면 기존 fallback을 따른다.

기존 0.65초 예측(30Hz에서 20step), 회전·벽 임계값, 매 tick 벽 회피와 출발 안전, 점수/RNG 추첨/주기/예약 규칙은 그대로다. ATTACK/RETURN/REPOSITION에 새 후보 필터를 적용하지 않았다. prefix 전체 예측과 다른 행동 수정도 넣지 않았다. 행동이 달라져 미래 RNG 소비가 달라지는 것은 이번 수정의 결과이고, 진단 유무에 따른 RNG 차이는 허용하지 않는다.

## 벽 근처 확장은 선택 후 실제 실행되는가

‘실행’은 계획 선택 직후 최종 안전 처리를 통과해 해당 확장의 입력을 낸 것(adopted)이다. 실제 외부 출발(launched)과 분리했다. 전체 궤적이 바뀌므로 기준의 특정 242개 계획을 새 궤적에서 일대일로 찾았다는 뜻은 아니다. 실행률은 올랐지만 실행 건수 974→850과 외부 출발 건수 611→556은 줄었다. 비율만으로 확장량 증가나 수익 개선을 주장하지 않는다.

같은 관측·같은 생성 후보 묶음에서 **예전 출발 안전만 적용한 첫 후보가 벽 회피로 RETURN이 될 상황**을 재계산했다. 그런 판단은 114건이었다. 새 선택이 같은 tick에 다른 EXPAND/STEAL 입력으로 실제 남은 경우는 **112건**이었다. 나머지 2건은 다른 목표/fallback이어서 대체 확장 성공으로 세지 않는다. 서로 달라진 두 세계의 같은 tick을 비교한 수치가 아니다. 이 읽기 전용 재평가와 선택 계측도 비간섭 검증에 포함했다.

## 공격 회귀와 검증

- 기존 중거리: **13/16**, 기존 실패 ID5·6·14 동일, **새 손실 0**. 성공 개수만 아니라 성공/실패 mask도 확인했다.
- known seed1: match115/탐험가/직접 memorySeed1/원래 사람 경로를 유지. ATTACK 0tick, 사람은 t76까지 살아 한 번 점령했다. 알려진 회귀 `it.fails`는 남아 있다.
- 확장 audit: 기존과 같은 고정 1,024사례, **155/1,024(15.14%)**. 사례별 성공/실패 **모두 동일**, 바뀐 사례 0. 근거리 155/896, 먼 배치 0/128이다. HUD observer on/off 44개 궤적·memory·다음 RNG·예약 동일.
- 먼 배치 공정성: 수정 소스에서도32개 초기 판단 검사 통과. 관측 밖 사람의 방향/입력을 바꿔도 해당 초기 입력·memory·다음 RNG·예약이 동일했다. 전체 경기의 숨겨진 위치 변경 동일성을 증명한 것으로 확대하지 않는다.
- 자연 8시드: 계측 소스와 해당 수정 native 소스의 **전체 궤적·최종 판단 trace·memory·다음 행동 RNG·예약 동일**. 성장 계측과 벽/대체 후보 계측을 각각 확인했다. 변경 전 행동과 동일해야 한다는 검사는 아니다.
- 새 테스트: 기록된 seed4 실제 조향의 벽 override 예측/경로 불변/다른 목표 제외, seed19 실제 움직임에서 후보 대체와 실행을 검증했다.
- 전체 Vitest 첫 실행: 98파일 중 96통과, 676통과/1기대 실패/4실패. 실패는 허용된 행동 변경 이전에 고정한 궤적 해시 4개였다. 해시를 갱신한 뒤 해당 2파일 16테스트 전부 통과했다. 기존 소유권·실제 점령·벽 사망0·성공 부활·안전지킴이 사망0/shape 제한 검사를 제거하지 않았다. 합계 680개 통과/기대 실패 1개이며, 갱신 후 전체를 다시 실행했다고 보고하지 않는다.
- 프로젝트와 변경 분석 스크립트 strict 타입 검사, production build 통과. PC 화면 테스트 **9/9** 통과. HUD/선택/사람 연습/14봇 관전/피해 표시/재배치/안전 진단을 확인했다. production HUD 비노출 유지.

## 다음은 실제 사람 플레이

실험 서버의 `/?debug=1&experimentSeed=19` 또는 seed47에서 닉네임을 넣고 **연습**을 누른다. `spectate=1`은 넣지 않고 ‘내 화면’으로 사람이 직접 움직인다. 이 모드는 사람1+봇13이라 자동 비교의 14봇 배치와 슬롯/tick이 같다고 가정하지 않는다.

모든 봇을 볼 필요는 없다. 가까운 가장자리 안전지킴이 하나와 영역도둑 하나를 중심으로 다음만 확인한다.

1. 벽 가까이서 확장을 골랐다 바로 취소하는 반복 대신, 다른 방향 확장으로 이어지는가.
2. 사람 선을 보면서도 쓸데없이 벽으로 밀거나, 반대로 벽 때문에 계속 순찰만 하는가.
3. 상대가 붙었을 때 안전 귀환과 평소 공격·되찾기가 지나치게 어색해지지는 않았는가. 특히 seed19·47의 사망 증가가 체감되는가.

실제 사람 플레이는 자동 화면 검증과 구분하여 아직 대기한다. 이 결과를 받은 뒤 (a) 보유 성장과 (c) 공격 접근 분석의 순서를 다시 정한다. 여기서 다른 안전 보완을 추가하지 않는다.

후속 후보로만 보존한다: **기준의 출발 이동 중 중단 417건 → 같은 검사를 prefix 전체로 넓히는 안**. 이번에는 구현하지 않았다. (c)의 핵심 질문도 기록만 한다: **12칸 배치에서 선을 관측하고도 절단 0인 이유**, **선사냥꾼 15.6%가 탐험가 16.8%보다 낮은 이유**. 공격 조건/안전 기준/확률을 조정하지 않는다.
