# 봇 AI 2단계 구현 결과

2026-10-10. 브랜치 `codex/bot-ai-phase01`. 승인한 초기값과 두 추가 조건을 반영했다. 게임 소스 기준값은 `41980bd`, 승인 조건 반영 제안은 `9501018`이다. **2단계 사용자 관전 확인 후 3단계 진행을 결정한다.**

## 구현한 동작

- 슬롯 기반 `grievances`, 칸마다 +1 적립, 기존 직접 점수 가산을 제거했다. 참가자 ID 기반 `grudge`만 사용하며 자기 사망·부활 이후에도 기억과 최근 사건 중복 방지·재적립 대기를 유지한다.
- 실제 점령 처리에서 사건 당시 관측 범위 안의 내 소유→상대 소유 변경만 집계한다. 점령 사건 ID당 한 번 적립하며 사망 시 중립화·단순 소유 변경·관측 밖 탈취를 피해 사건으로 만들지 않는다. 봇에 전달하는 사건에는 상대 위치·선·이동 방향이 없다.
- 사망 +5, 6칸 이상 점령 사건 +3, 접근/침입 반복 2회와 0.5초 재진입 확인, 2초/4초 재적립 대기, 원한 상한 20을 적용했다. 같은 진입의 접근·침입은 큰 가중치만 남기며 판단 틱이 달라도 중복 가산하지 않는다.
- 일반 반감기 45초, 복수심 90초, 직접 처치 ×0.25 / 다른 사망 ×0.5, 0.1 미만 삭제를 적용했다. 상대 이탈·ID 교체 시 이전 원한을 정리한다.
- 기억에 의한 `valuable`은 원한 원값 **6 이상**이다. 사망 1회(+5)와 복수심 점수 배율만으로 넘지 않는다. 기존 현장 침범·짧은 절단 기회와 성격별 제한은 유지한다. 원한 직접 가산은 `min(12, 0.6 × grudge × 복수심 배율)` 한 경로다.
- `pressure = (0.5 × 선 위협 + 0.35 × 최근 10초 관측 피해) / 0.85`를 상승 1초·하강 4초로 평활화한다. 확장 최대 −8%, 위험 가중 최대 +10%를 기존 성격 범위 안에서 임시 적용한다. 점유율 격차는 HUD 표시 전용이다.
- 복수심을 자동 특성 배정에 활성화했다. 안전지킴이+도박꾼 제외와 배정/행동 RNG 분리를 유지하며 집요함은 3단계까지 비활성이다.
- 연습과 서버가 같은 디렉터를 사용한다. 실제 판단할 봇만 별도 RNG 도메인 `0x3b82af`로 셔플하고 대상당 계획 추격 예약 3명, 다른 예약 0/1/2명 배율 1/0.65/0.35, 800ms 만료를 적용한다. 선택 직후 원자적으로 반영하며 사망·이탈·목표/생명 변경·경로/선 무효 시 해제한다. 사람과 봇 대상에 같은 제한을 적용하고 사람 입력 의도는 집계하지 않는다.
- 실제 위협 상대에 대한 빠른 역절단만 예약 상한 예외다. 승인한 ETA와 여유 조건, 기존 공격 안전 검사를 모두 충족해야 한다. 위협이 사라진 뒤에는 정상 예약을 다시 요구한다. 예외 통계는 **선택된 예외 판단 횟수**다.

기존 공격 대상 유지 정책과 일반 짧은 역공 판정은 보존했다. 더 넓은 계획 무효화·목표 유지 시간·3층 판단은 3단계 범위다. 원한이 높아도 관측 밖 상대 추적이나 멀리 있는 방어 지점으로 자동 귀환하지 않는다.

## 검증

타입 검사(클라이언트·서버·테스트와 audit 스크립트 별도 검사), 빌드, Vitest **83파일 543개**, Playwright **3개**가 통과했다. 2단계 추가 테스트는 원한 기준 경계·점수 이중 가산·실제 점령 사건·관측 제한·부활·감쇠·사건 중복·반복 진입·pressure 범위·순위 비간섭·예약 상한·생존 예외를 검증한다. HUD 유무에 따른 실제 입력·게임 상태·행동 RNG·예약 순서도 일치한다.

기존 반복 침범 테스트는 한 칸 탈취 두 번으로 공격한다는 기대를 실제 6칸 이상 점령 사건 세 번으로 교체했다. 두 번의 +3은 감쇠로 6 미만이다. 6 아래로 진정하는 시점과 0.1 미만 삭제를 나누어 검증했다. 기존 즉시 공격·대상 유지·귀환·중거리 공격 테스트는 유지했다.

고정 궤적 hash는 새 기억 구조에 맞춰 갱신했으며 소유량 일치·실제 점령·벽 사망 0·성공한 리스폰의 독립 조건을 추가했다. R5 서버 벽 테스트의 무작위 스폰 실패는 이전 코드에서도 seed 13으로 재현됐다. 게임 규칙을 변경하지 않고 해당 전송/벽 fixture만 유효한 seed 4로 고정했다.

## 동일 조건 비교

R56 / 스폰 7칸 / 14 BOT / 안전 리스폰 켬 / `botSeed` / 시드 4·19·73 / 각각 120초다. 이전 코드를 별도 디렉터리에서 재실행해 기존 27,559칸·1,845회 점령·29회 사망이 정확히 재현되는 것을 확인했다. 동일한 성장 진단도 추가해 측정했다.

**seed 4의 사망은 10→16회로 증가했다.** seed 19는 11→7, seed 73은 8→5다. 세 시드 합계만으로 모든 상황에서 생존이 개선됐다고 결론내리지 않는다. 복수심 배정 후보 추가로 같은 시드의 특성 조합도 달라지는 전체 2단계 변경 비교다.

순영토 증가는 실제 보유량 변화에서 사망 중립화 손실과 리스폰 지급을 분리한 값이다. 분·시간당 증가와 생명별 최대 점유율을 참가자별로 저장했다. 최대 점유율은 매 tick 경계와 사망 중립화 직전의 표본이며 모든 소수 tick 순간의 최대치는 아니다. 취소/조기 귀환 비율의 분모는 출발 전에 취소한 계획도 포함한 모든 선택 확장 계획이다.

기존 밀집 사망 fixture는 **R22 / 스폰 19칸 / 안전 리스폰 끔 / seed+slot**, 8시드 × 14 BOT 또는 2 HUMAN+12 BOT의 16게임이다. 718회 사망 중 BOT 709회 / HUMAN 9회, BOT 벽 사망 0, HUMAN 벽 사망 7, 사망 처리 검증 오류 0이다. 기준 fixture의 749회 사망과 구분해 비교할 수 있다. 중거리 공격 fixture **16개 모두 실제 선 접촉 절단**을 확인했다.

자연 대전의 계획 추격 예약 최대는 R56에서 1명, 밀집 fixture에서 2명이었다. 밀집 fixture에서 생존 예외 판단 41회가 발생했지만 상한이 차 있는 예외는 없었다. **3명 상한·같은 tick 반영·상한 중 역공·위협 해소 후 정상 제한은 통제된 자동 테스트로 별도 검증했다.** 짧은 성격 audit의 공격 표본은 작으므로 성공률을 일반화하지 않는다.

같은 PC에서 다른 검증 프로세스 종료 후 순차 측정한 중앙값은 기준 **2.636ms/tick**, 2단계 **2.612ms/tick**, 2단계 HUD 수집 포함 **2.739ms/tick**이다. 워밍업 1회 제외·1,800tick × 3회이며 DOM·렌더·여러 방 부하를 포함하지 않는다. 작은 차이를 성능 향상이라고 단정하지 않는다.

## 관전에서 확인할 부분

개발 서버 `http://127.0.0.1:5180/?debug=1&spectate=1&experimentSeed=19`를 새로고침하고 14봇 관전을 시작한다. 일반 게임과 배포 빌드에는 디버그 HUD/사람 없는 관전이 노출되지 않는다.

- 피해·사망 후 같은 상대 원한이 쌓이고, 자기 부활 이후에도 남는지 확인한다. 6은 기억에 의한 가치 기준이며 모든 공격의 필수 조건은 아니다.
- 복수심이 안전 조건을 통과하는 같은 상대 기회를 더 선호하는지, 시간이 지나면 진정하는지 본다. HUD에서 원한 직접 점수와 후보 공격 계수를 따로 볼 수 있다.
- 최근 피해·선 위협에 pressure가 반응하는지, 점유율 격차만으로 행동이 바뀌지 않는지 본다. 예약 거절 이유와 생존 예외는 최신 후보/계획 생성 판단에 표시된다.
- 앞서 관찰한 반복 침범 무대응·세 봇 근접 장면을 다시 본다. 후보의 경로·귀환·거리 제한인지 목표 유지 문제인지 HUD 이유를 남긴다. seed 4도 함께 확인한다.

사용자 관전 확인 전에는 3단계에 착수하지 않는다.
