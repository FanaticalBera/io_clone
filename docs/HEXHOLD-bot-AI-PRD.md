# HEXHOLD 봇 AI 개선 PRD

Oct 9, 2026 · @ablazet · 수정본 v0.5 · 0+1단계 관전 검토 반영

## 1. 개요

**목표:** 봇마다 플레이 스타일이 보이고, 예측하기 어렵지만 납득할 수 있는 상대를 만든다. 플레이어가 "또 AI 패턴이네"가 아니라 "저놈은 왜 저러지?"라고 느끼는 상태가 성공이다.

- 사람을 흉내 내는 것 자체는 목표가 아니다. 봇을 일부러 못하게 만들지 않는다.
- "사람처럼 보이게"와 "게임을 더 잘하게"는 분리해서 다룬다.
- 연습 모드 기준 구성은 유저 1 + 봇 13(총 14명)으로 확정한다. 성격 배분 구현은 실제 봇 수에 따라 동작한다.

**범위:** 봇 성격 배정, 개인차, 2차 특성, 기억(원한), 판단 주기, 확장 패턴, 전략 판단, 봇 닉네임 풀, 연습 모드용 디버그 HUD.

**범위 밖:** 이동 물리·속도·회전, 점령·사망·리스폰 규칙, 온라인 디버그 프로토콜, 리플레이 시스템. 난이도는 맨 마지막 단계로 미룬다.

**선행 정합 확인:** 사용자에게 전달된 최신 master 코드 확인 결과에 따르면 `maxSlots: 14`와 안전 리스폰이 이미 반영되어 있다. 과거 `maxSlots: 16` 분석은 이전 커밋에서 갈라진 worktree 기준이었다. 구현 전에는 UI 개편 등 진행 중인 변경을 보존하면서 최신 master를 통합하고, 총 참가자 상한 14명·연습 봇 13명·안전 리스폰의 반영 여부를 확인한다. 이미 반영된 설정이나 리스폰을 중복 구현하지 않는다. 온라인은 총 14명에서 사람 수를 뺀 만큼 봇을 채운다. AI 변경 전후는 같은 14명 구성으로 비교한다.

**이번 문서 수정 범위:** PRD만 수정한다. worktree 통합과 코드 구현은 실제 구현 착수 시 수행하며, 첫 구현 묶음은 0+1단계까지다.

## 2. 현재 봇의 문제 (기존 코드 분석 기준)

지금 봇은 상태 기계(`EXPAND / STEAL / SEEK_POINT / ATTACK / RETURN / ESCAPE`)와 경로 후보 점수로 움직이며, 전술은 정밀하지만 봇끼리 구별이 안 되고 큰 그림이 없다. 주요 코드는 `src/shared/bot.ts`(450줄)다.

| 영역 | 현재 상태 | 체감 문제 |
| --- | --- | --- |
| 닉네임 | 4개 이름이 성격과 1:1로 묶여 반복 | 이름만 보고 봇이고 성격까지 앎 |
| 성격 배정 | `i % 4`로 슬롯 고정 | 같은 판을 반복하면 패턴이 읽힘 |
| 개인차 | 특성 3개가 ±10%만 변동 | 같은 성격끼리 거의 똑같이 움직임 |
| 기억 | 새 생명에서 원한(`grievances`) 초기화 | 죽으면 원한을 잊음, 악연이 안 생김 |
| 판단 주기 | 모든 봇 200ms 동일, 위험 감지도 같은 주기 | 반응이 모두 똑같고 기계적 |
| 확장 모양 | 선택 계획의 약 63\~70%가 평행사변형 계열 | 다이아몬드 반복으로 보임 |
| 확장 규모 | 경로 최대 24칸, 선 한도 12\~20칸, FB3 후 평균 점령 11.2 → 9.9칸 | 살아남지만 이기려고 하지 않음 |
| 전략 | 반경 12칸 안의 전술 판단만 있음 | 순위·1위 견제·빈 땅 방향 감각이 없음 |
| 타깃 쏠림 | 봇끼리 서로의 목표를 모름 | 원한·견제를 넣으면 한 사람에게 몰릴 위험 |

참고: 이 절은 과거 분석의 진단 기록이며 최신 master 현황표가 아니다. 줄 수·개인차·확장 통계 등은 원본 PRD 작성 시 분석한 코드 기준이고, 최신 코드와 이번 문서 수정에서 직접 대조하지 않았다. 참가자 수와 자기 선 판정 정정은 사용자가 전달한 코드 확인 결과를 반영했다. 구현 시작 시 실제 구조를 확인하고 이미 적용된 작업은 중복 구현하지 않는다. 과거 `maxSlots: 16` / 연습 봇 15명은 현재 기준이 아니다.

## 3. 설계 원칙과 확정 규칙

모든 단계는 아래 원칙을 따른다. 정해진 규칙은 다시 논의하지 않는다.

**원칙**

1. 같은 상황에서 봇마다 다른 선택을 하게 만든다. 랜덤 실수나 흔들림으로 인간성을 만들지 않는다.
2. 성격(archetype)의 정체성은 어떤 변화에도 깨지지 않는다. 개인차·감정·특성은 성격별 범위 안에서만 움직인다.
3. 판정 경로와 화면 위치는 일치해야 한다. 렌더링만 보정하는 일은 하지 않는다.
4. 반응 지연은 전략 판단에만 주고, 최소한의 생존 본능은 느리게 하지 않는다.
5. 정보 공정성: 사람도 보는 정보(순위표·점유율)만 전역으로 주고, 위치·선·이동 방향은 관찰 범위 안에서만 알게 한다.
6. 새 동작은 작게 시작하고, 효과가 확인된 뒤 늘린다.

**확정 규칙**

| 항목 | 규칙 |
| --- | --- |
| 닉네임 | 사람이 지을 법한 이름 수백 개를 풀로 준비하고 매 판 랜덤 배정한다. 성격과 완전히 분리하며, `영역탐험가` 등은 내부 archetype 이름이 된다(HUD에서만 표시). 사람과 다른 봇을 포함한 참가자 닉네임과 중복되지 않게 뽑는다. 도중 투입 봇도 똑같이 확인한다. 1단계는 배정 구조만 구현하고, 200~300개 목록 완성은 마지막 다듬기 단계로 미룬다. |
| 성격 배분 | 봇 수를 4성격에 균등 배분한다(13명 → 4/3/3/3). 어느 성격이 +1을 받을지는 시드로 바뀐다. 슬롯은 매 판 섞는다. 도중 새로 투입된 봇은 현재 구성에서 부족한 성격을 우선 배정하고 동률이면 시드로 선택한다. 기존 참가자의 사망 후 부활에는 성격·특성을 유지한다. |
| 개인차 | 성격별 범위 안에서 랜덤화한다. 예: 선사냥꾼 공격성 0.80\~1.00, 위험감수 0.60\~0.90. |
| 2차 특성 | 봇마다 1개. 충돌하는 조합(예: 안전지킴이 + 도박꾼)은 빼거나 약하게 한다. |
| anti-dogpile | 사람·봇 모든 대상에게 동일하게 적용하는 디렉터 규칙이다. 봇의 계획적인 추격 예약만 집계한다. 두 번째 예약 ×0.65, 세 번째 ×0.35 점수 패널티 + 예약 최대 3명. 사람의 공격 의도는 집계하지 않는다. 즉각적인 생존 역공은 예외로 허용하고 별도 계측한다. |
| 테스트 | 실제 게임은 시드 기반 배정, 테스트는 슬롯별 성격·특성을 직접 지정할 수 있어야 한다. 새 배분·셔플도 별도로 검증한다. HUD·observer는 판단 결과와 행동 RNG 소비를 바꾸지 않는다. |
| 봇 수 | 연습 모드는 유저 1 + 봇 13, 총 참가자 상한은 14명으로 확정한다. 온라인 봇 수는 사람 수에 따라 달라진다. 성격 배분은 실제 봇 수를 사용하며 13명이나 4×4에 고정하지 않는다. |

## 4. 전체 구조

| 구성 | 내용 | 적용 시점 |
| --- | --- | --- |
| 정체성 | archetype, 성격별 개인차, 2차 특성 | 판 시작·새 참가자 투입 시 배정; 같은 참가자 부활 시 유지 |
| 상황 | 지역 관찰, 자기 영토·선 상태, 원한 기억, 공개 순위 정보 | 판 도중 갱신; 해당 단계에서 추가 |
| 즉시 안전 | 벽·인접한 치명적 위협 확인 | 매 tick, 가벼운 계산만; 자기 선은 치명적 충돌 대상이 아님 |
| 전술 안전 | 선 위험·귀환 ETA·역공 가치 평가 | 빠른 주기 |
| 전략 판단 | 확장·공격·도둑질·목표 변경, 성장 정체 대응 | 주기 개인차는 3단계, 성장 정체 대응은 4단계 |
| 출력 | 기존 이동 시스템에 방향 입력 전달 | 안전 판단이 전략 계획보다 우선 |

정체성과 상황을 판단 3층에서 함께 사용한다. 3층 분리는 3단계에서 구현하며, 0+1단계에서는 기존 판단 구조를 유지한다.

## 5. 로드맵

| 단계 | 작업 | 목적 |
| --- | --- | --- |
| 선행 | 작업 변경 보존·최신 master 통합·14명 및 안전 리스폰 확인 | 최신 기반과 같은 밀도에서 전후 비교 |
| 0 | 개발용 관전 디버그 HUD | 행동 이유를 관찰 |
| 1 | 성격 셔플·개인차·2차 특성·닉네임 배정 구조 | 봇별 반복감 감소 |
| 2 | 참가자 ID 기반 사건 기억·감쇠·공개 순위·추격 예약 | 관계 형성 및 공격 쏠림 완화 |
| 3 | 판단 3층 분리·주기 개인차·계획 유지와 무효화 | 안전성과 반응 다양성 확보 |
| 4 | 확장 출발점·방향·규모 다양화·순성장 정체 대응 | 반복 패턴 감소 및 실제 성장 개선 |
| 5 (선택) | 전략 레이어·1위 견제·영향 지도 | 큰 그림 판단 |
| 6 (선택) | 필요할 경우 Utility AI 통합 | 행동 선택 구조 정리 |
| 마지막 | 닉네임 목록 완성·검토, 이후 난이도 | 콘텐츠 다듬기와 완성된 AI의 변형 |

0\~4단계가 본 작업이고, 5·6단계는 1\~4단계만으로 충분히 재미있으면 생략한다. 난이도는 기본 AI가 완성된 뒤에만 만든다.

## 6. 단계별 상세 요구사항

첫 구현 묶음은 0단계와 1단계다. 각 단계는 사용자가 관전으로 확인한 뒤에 다음 단계로 넘어간다.

### 0단계 — 디버그 HUD

- 연습 모드 + 개발용 플래그에서만 켜진다. 기존 `diagnostics` 옵션과 `watchBotDecisions` 위에 만든다. 온라인 프로토콜은 바꾸지 않는다.
- 봇별 요약: 번호, archetype, 2차 특성 및 활성 여부, 현재 상태, 공격 대상, 선 길이, 위험도.
- 선택한 봇 하나의 상세: 최신 판단과 현재 계획을 세운 판단을 따로 표시한다. 계획 생성 당시 선택 이유·공격 후보와 거절 사유·확장 상위 후보·거절 집계를 보존하며 계획 변경 때만 갱신한다. waypoint 진행이나 PLAN_CONTINUE로 덮지 않는다.
- debug=1 + development/test에서만 사람 없이 14봇으로 관전하는 별도 세션을 제공한다. 일반 연습의 사람 사망·입력·보상 규칙은 유지한다.
- 기존 거절·공격 포기·놓친 기회 진단 기록을 우선 활용한다. `VICTIM_RETURNS_FIRST`, `COUNTER_CUT_FIRST` 등의 실제 사유가 기록되는 경로를 확인하여 노출한다. 없는 사유를 추정해서 만들어 표시하지 않는다.
- 대안 설명은 실제 판단에서 이미 계산한 내용만 사용한다. HUD를 위해 별도 후보 탐색이나 판단 시뮬레이션을 실행하지 않는다. 전환 이력은 길이가 제한된 버퍼로 유지한다.
- 상태별 색: 실제 상태 6개(`EXPAND / STEAL / SEEK_POINT / ATTACK / RETURN / ESCAPE`)에 맞춘다.
- 1단계 자동 배정은 작동하는 4개 특성(Coward/Gambler/Opportunist/Territorial)만 사용한다. Vengeful·Persistent는 정의와 명시적 실험 배정만 유지하며, 이 경우 비활성으로 표시한다. 원한·pressure·추격 예약 등 아직 없는 값은 해당 구현 단계에서 추가한다.
- HUD·observer 활성 여부가 판단 결과와 행동 RNG 소비에 영향을 주어서는 안 된다.

### 1단계 — 성격 다양화 + 닉네임 배정 구조

- `i % 4` 고정 배정을 없애고, 균등 배분 + 시드 셔플로 바꾼다.
- 성격별 특성 범위를 넓힌다(현재 ±10%).
- 성격 배분·셔플, 개인차·2차 특성 추첨은 시드에서 파생한 전용 RNG를 사용한다. 행동 RNG를 소비하지 않으며 닉네임·예약 순서 RNG와도 분리한다.
- 2차 특성 6개를 정의하고 봇마다 1개를 붙인다.
  - 즉시 작동: 겁쟁이(Coward), 도박꾼(Gambler), 기회주의(Opportunist), 영토집착(Territorial). 기존 평가 항목(위험 가중치, 루프 크기, 공격 확률, 방어 보너스)의 가중치를 조절한다. Territorial은 자기 영토 침입에 대한 방어 보너스에 기여할 수 있도록 적용 조건을 최소 확장한다. 기존 Guardian의 기본 보너스를 보존하고 최종 효과는 성격별 범위 안으로 제한한다.
  - 자동 배정 제외: 복수심(Vengeful)은 2단계, 집요함(Persistent)은 3단계에서 효과가 켜질 때 배정 후보에 넣는다. 정의는 유지한다.
- 닉네임 풀을 성격과 분리하고, 매 판 랜덤 배정·참가자 간 중복 방지·도중 투입 시 재확인 구조를 만든다. 이미 있는 이름 목록을 재사용하되, 13봇 배정과 중복 방지 확인에 필요한 만큼만 보충한다.
- 200~300개 목록 완성과 사용자 검토는 마지막 다듬기 단계다. 이름 콘텐츠 제작 때문에 0+1단계 구현과 행동 검증을 지연하지 않는다.
- 닉네임 추첨은 별도 RNG를 쓴다(마커 섞기와 같은 방식). 봇 판단 RNG를 소비하지 않는다.
- 테스트용 슬롯별 archetype·특성 지정 옵션을 둔다. 균등 배분·셔플·시드 재현성 테스트는 이 지정 옵션과 별도로 검증한다.
- 새 참가자로 도중 투입되는 봇은 현재 구성의 부족한 성격을 우선 배정하고, 동률이면 시드로 선택한다. 기존 봇의 사망 후 부활은 같은 성격·특성을 유지한다. 성격 배정은 참가자 정체성에 속하며 슬롯 자체에 묶지 않는다.

### 2단계 — 기억과 anti-dogpile

**기억과 사건 집계**

- 원한의 키는 슬롯이 아니라 참가자 ID다. ID는 같은 참가자의 생명 교체에는 유지되고, 슬롯을 물려받은 새 참가자에게는 새로 부여되어야 한다. 이 조건을 현재 참가자 관리와 안전 리스폰 흐름에서 확인한다.
- 같은 참가자의 사망·리스폰 대기·부활에 원한을 유지하고 시간에 따라 감쇠시킨다. 새 참가자에게 이전 참가자의 원한을 넘기지 않는다.
- 원한은 관찰 가능한 사건으로만 쌓는다. 상대의 의도는 추측하지 않는다. 높은 원한이 관찰 범위 밖 상대의 현재 위치·선·이동 방향을 공개하지 않는다.

| 사건 | 원한 변화와 집계 단위 |
| --- | --- |
| 나를 죽임 | +5, 한 사망 사건당 한 번 |
| 내 영토를 N칸 이상 빼앗음 | +3, 한 점령 사건의 여러 칸 탈취를 하나로 집계 |
| 상대 머리가 내 노출 선 근처로 접근 | 단발 접근은 위험도에만 반영; 원한은 반복 접근 시 약하게 반영 |
| 짧은 시간 반복 침입 | +1을 초기 후보값으로 사용; 동일 사건 중복 적립 금지 |
| 시간 경과 | 서서히 감소 |
| 내가 그 상대를 처치 | 크게 감소 |
| 그 상대가 다른 이유로 사망 | 일부 감소 |

- 접근 사건은 정의한 거리 범위 밖에서 안으로 들어오는 순간에만 기록한다. 안에 머무르는 동안 판단마다 재적립하지 않는다.
- 같은 참가자·같은 사건 종류에는 재적립 대기 시간을 적용한다. 반복 접근과 반복 침입이 같은 사건이면 중복 적립하지 않는다. N, 접근 거리, 반복 기준, 대기 시간, 약한 가중치·감쇠값은 2단계 착수 시 정한다. 기존 ‘접근마다 +2’ 규칙은 사용하지 않는다.
- 기존 슬롯 기반 `grievances`는 참가자 ID 기반 `grudge`로 완전히 교체한다. 옛 공격 점수 `+min(12, grievance)`와 성격별 원한 가치 기준을 제거한다. 기억에 의한 `valuable`은 감쇠된 원한 원값 6 이상으로 시작하며, 사망 1회(+5)나 Vengeful 점수 배율만으로 충족하지 않는다. 현장 침범·유효한 즉시 공격 조건과 안전 제약은 유지한다.
- 감정은 `pressure`(선 위협·최근 관측 피해)와 `grudge`(특정 상대 기억) 2개로 시작한다. 효과가 확인되면 confidence·fear로 나눈다.
- 공개 순위·점유율 격차는 2단계에서 HUD 표시용으로 추가하며 `pressure`와 행동 판단에는 사용하지 않는다. 순위가 행동에 주는 영향은 4–5단계에서 다시 정한다. 위치·선·이동 방향은 지역 관찰 제한을 유지한다.
- 감정은 기존 조절값에만 영향을 주고 성격 범위로 제한한다. 예: 안전지킴이 공격성은 화가 나도 0.20 → 최대 0.45. Vengeful 효과는 이 단계에서 활성화한다.

**공격 쏠림 제어**

- anti-dogpile은 방(room)과 연습 모드의 디렉터가 관리한다. 예약 현황을 개별 봇의 전역 위치 지식으로 제공하지 않고, 계획적인 추격 선택의 점수·허용 여부를 제어한다.
- 집계 대상은 봇이 계획적인 ATTACK으로 선택한 대상 예약이다. 공격 대상이 사람인지 봇인지에 관계없이 같은 규칙을 적용한다. 사람의 공격 의도는 추정하거나 공격자 수에 포함하지 않는다.
- 기존 예약 0개면 점수 ×1, 1개면 ×0.65, 2개면 ×0.35, 3개면 추가 계획 추격을 허용하지 않는다. 갱신 시 자신의 기존 예약을 중복 집계하지 않는다. 패널티 값은 초기 튜닝값이다.
- ATTACK 진입 결정 시 예약을 원자적으로 반영하고, 같은 tick의 다음 봇 판단은 앞선 예약을 반영한다. 모든 봇이 갱신 전 빈자리를 보고 동시에 예약하는 방식을 사용하지 않는다.
- 실제 판단하는 봇들만 대상으로 시드 기반 순서 셔플 또는 회전을 적용한다. 낮은 슬롯이 항상 먼저 배정받지 않게 한다. 셔플에는 별도 RNG를 사용하며 행동 RNG를 소비하지 않는다. HUD·observer 유무도 배정 순서에 영향을 주지 않는다.
- ATTACK 이탈·대상 변경·공격자 사망 또는 이탈·대상 사망 또는 이탈·추격 무효화 시 예약을 해제한다. 유효한 추격 중 갱신하고, 갱신이 끊긴 예약에는 만료 시간을 둔다. 만료 시간은 판단 주기를 고려해 정한다.
- 즉각적인 생존 역공은 추격 제한보다 우선하며 예약 상한의 예외로 허용한다. 일반 추격을 예외로 우회하지 않도록 현재 관찰된 치명적 위협과 기존 역공 판정에 근거한다. 위협이 사라진 뒤 추격을 이어가려면 정상 예약을 받아야 한다.
- 예외 역공 횟수와 상한 초과 시 발생한 예외를 별도로 계측한다. 검증 조건은 ‘모든 공격 최대 3명’이 아니라 ‘계획적인 추격 예약 최대 3명’이다.
- 1위 견제(`leaderThreat`)는 독립 성격이 아닌 가중치다. 실제 적용은 5단계이며, 2단계에서 순위 정보를 추가하는 것과 구분한다.

### 3단계 — 판단 구조 분리·전술100ms

판단을 3층으로 나눈다. 2026-10-13 최종 승인에서 개인별 전략 주기는 되찾기·성격 정체성 손실로 미채택이며 정의만 비활성 보존한다. 아래는 실제 채택한 주기다.

| 층 | 주기 | 내용 |
| --- | --- | --- |
| 즉시 안전 | 매 tick, 아주 싼 계산만 | 다음 칸이 벽인가, 바로 인접한 치명적 위협이 있는가 |
| 전술 안전 | 3tick / 100ms | 내 선 전체 × 주변 적 거리, 귀환 ETA, 역공 가치 |
| 전략 판단 | 6tick / 200ms·slot%6 위상 | 확장, 공격, 도둑질, 목표 변경 |

- 최초 개인별 전략 주기 제안은 미채택이다. 다시 활성화하려면 성장·되찾기·성격 지표와 비용을 별도로 검토·승인한다. 500ms에 접근하는 주기를 자동으로 허용하지 않는다.
- 자기 선 접촉은 현재 절단 사망 조건이 아니다. 필요하면 되짚기·불필요한 교차를 경로 품질 평가에서 다루고, 치명적 충돌 회피로 취급하지 않는다.
- 기존의 비싼 `danger` 전체 계산을 매 tick 옮기지 않는다. 전술 안전 계산은 빠른 별도 주기로 수행하고 `bot-performance`로 비용을 확인한다.
- 계획 유지 시간보다 유효성 확인이 우선이다. 목표 사망·대상 선 소멸·귀환 지점 탈취·관측 정보 만료·진행 불가 또는 정체 시에는 유지 시간을 무시하고 재판단한다.
- 기존 목표 소멸·귀환로 상실·진행 정체 처리도 분리 과정에서 보존한다. ESCAPE와 즉각적인 생존 역공은 유지 시간보다 우선한다.
- 유효한 계획을 보존하고 무효한 목표·실패한 경로는 고집하지 않는다. 최소 유지와 Persistent 효과를 넣기 전에 실제 적용 대상을 측정한다. 2026-10-12 기준에서 600ms/공격 300ms 규칙의 적용 대상이 0회여서 유지 배율을 보류하고, 같은 피해 구역·대상을 다음 계획에서도 우선하는 연속성 가산 대안을 제안한다. 효과와 배정 활성화는 별도 승인 후 진행한다.
- 귀환 재정비(2026-10-12 사용자 검토): 다음 계획의 출발 경계까지 자기 영토 안에서 이동하는 구간으로 정의하는 안을 우선 검토한다. 기존 prefix를 활용하며 고정 대기/불필요한 왕복을 강제하지 않는다. 별도 고정 시간이 필요하면 0~400ms부터 승인 후 비교하고 보유 시간 평균 영향을 보고한다.
- 채택한 전략 판단은 기존 slot%6 위상을 유지한다. 전술은 분리된 개인별 위상을 사용하며 행동 RNG를 소비하지 않는다.

### 4단계 — 확장 개선

- 자기 영토의 최근 순증가가 정체되면 출발점·확장 방향·규모를 재선택한다. 총 점령량이나 루프 성공 횟수만으로 성장했다고 판단하지 않는다. 생존 중 성장 정체와 사망·리스폰 대기를 구분한다.
- 위협·중립 공간·귀환 가능성과 예상 노출 시간을 함께 평가해 평소보다 큰 루프를 허용한다. 위험 지역에서는 작은 루프를 쓴다. 탐험가·도박꾼은 큰 루프를 더 선호하되 성격별 위험 범위를 유지한다.
- 적이 관찰되지 않아도 안전을 보장하지 않는다. 노출된 선의 위치, 관찰 범위 경계에서 적이 접근할 가능성, 중간에 짧게 닫을 귀환 경로를 고려한다. 관찰 범위 밖 적의 실제 위치·이동 방향을 사용하지 않는다.
- `12칸 / 4.2칸·초⁻¹ ≈ 2.9초`는 특정 거리의 이동 시간 계산 예시일 뿐 안전 보장 시간이 아니다. 노출된 선이 적에게 더 가깝거나 양쪽이 이동할 수 있다. 고정된 안전 시간이나 무조건적인 큰 루프 허용 기준으로 쓰지 않는다.
- 큰 루프에서도 전술 재평가와 조기 귀환을 유지한다. 귀환로 상실·치명적 위험·진행 불가 시 계획을 무효화한다.
- 모양 다양성은 같은 상황에서 선택하는 출발점·방향·크기가 달라지는지를 먼저 본다. 효율적인 사각형·평행사변형을 선택하는 것 자체를 실패로 판단하거나, 비율을 낮추기 위해 불필요한 경로를 강제하지 않는다.
- 기본 성장 대응은 이 단계의 필수 범위이며, 영향 지도나 1위 견제 구현을 전제로 하지 않는다.

### 5단계 — 전략 레이어 (선택)

- 2단계에서 제공한 공개 순위·점유율 정보를 활용해 `leaderThreat` 가중치를 적용한다. 1위의 정확한 위치·선은 지역 관찰 안에서만 사용한다.
- 간단한 영향 지도(influence map)로 어디가 안전하고 어디가 먹을 만한지 판단한다.
- 1\~4단계만으로 충분히 재미있다면 생략할 수 있다. Utility AI 통합도 마찬가지다.

### 6단계 — Utility AI 통합 (선택)

- 앞 단계의 상태 기계와 점수 조절만으로 충분하면 진행하지 않는다.
- 행동 선택 조건이 복잡해져 유지보수가 어려울 때만 기존 평가 항목을 공통 점수 구조로 정리한다. 프레임워크 도입 자체를 목표로 삼지 않는다.

### 마지막 — 닉네임 콘텐츠와 난이도

- 닉네임 풀을 200~300개로 완성하고 실존 유명인·욕설을 제외한다. 목록은 사용자 검토를 받는다.
- 매 판 랜덤 배정과 성격 분리는 1단계 구현을 유지한다.
- 난이도는 기본 AI의 행동이 안정되고 재미가 확인된 뒤에만 설계한다.

## 7. 검증 방법

**공격 합격 판정 변경 — 2026-10-14 사용자 승인:** 중거리 원래 16개는 계속 실행하고 성공·새 손실·회복 사례를 모두 기록한다. 새 손실이 나오면 고정 배치·memorySeed·사람 루프의 확장 1,024개 실제 선 절단 audit을 확인한다. 같은 기준군 대비 전체 성공 수가 나빠지지 않으면 공격 항목은 통과로 본다. 사례별 성공→실패/실패→성공도 숨기지 않는다. 아래 과거 기록의 ‘16개 새 손실 0’은 이 판정으로 대체한다. 안전·보유·비용·전체 테스트의 별도 조건은 유지한다. C의 10·13·16번 실패는 **C의 알려진 대가**이며, 5번 회복도 함께 남긴다. 기존 seed1 fixture와 기대 실패 기록은 별도로 유지한다.

자동 검증으로 정합성과 퇴보를 확인하고, 사용자는 HUD 관전으로 성격 차이와 재미를 판단한다. 사용자에게 회귀 검증을 직접 플레이로 대신 수행하게 요구하지 않는다. 아래 항목은 해당 기능이 구현되는 단계부터 적용한다.

- **관전 확인:** ‘봇마다 달라졌는가’, ‘왜 선택·포기·귀환했는지 설명되는가’를 확인한다. 상황에 따라 모든 성격이 귀환·공격할 수 있으며 특정 행동만 강제하지 않는다.

| 성격 | 관전에서 볼 주요 차이 | 함께 비교할 지표 |
| --- | --- | --- |
