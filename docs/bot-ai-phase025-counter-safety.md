# 위험 중 짧은 역공의 생존 자격 제한

2026-10-10. 사용자 승인한 조건 하나를 적용했다. **전체 균형은 재검토 상태를 유지한다.** 원래 기준군 사망 94→114회(+21.3%)로 +20% 재검토 기준을 넘는다. REPOSITION 추가 튜닝과 3단계는 진행하지 않았다.

## 변경 범위

위험(danger) 상황에서 귀환·회피를 대신하는 counterStrike에 기존 attack.survival=true를 추가 요구했다. 공격 시작과 공격 유지에 같은 조건이 적용된다. danger=false인 일반 공격은 기존 조건이며, 기존 1초/0.75초/0.15초 수치를 그대로 사용한다. D/V/P, 재배치 거리·대기·목적지, 성격 계수, 예약, 판단 주기, 실제 이동·점령·부활·동시 사망 규칙은 바꾸지 않았다. RNG 호출도 추가하지 않았다.

COUNTER_STRIKE라는 기존 진단 라벨과 추격 예약 상한을 우회하는 엄격한 survival 판정은 원래 별개였다. 이번 수정은 위험 중 회피를 덮는 조건에 엄격한 판정을 연결하는 행동 변경이다.

## 원래 장면의 동일 상태 검증

seed 137의 수정 전 #9 tick3591과 #4 tick3592를 재생했다. 같은 경기 상태·감정·경로를 복제하고, 별도의 행동 RNG를 원래 소비 횟수까지 진행한 뒤 새 판단을 평가했다. #9는7057회, #4는6107회 소비 상태다. 두 봇 모두 SELECTABLE 짧은 공격 후보가 있으나 survival=false였으며, 새 판단은 ESCAPE/DANGER다. 원래 세계 재생의 3600tick 해시도 이전 기록과 정확히 일치했다.

이는 원래 상태의 잘못된 위험 중 공격 선택을 제한했음을 보여준다. 새로운 전체 경기에서는 더 이른 판단부터 궤적이 달라지므로, 원래 tick3596의 두 사망만 제거했다고 주장하지 않는다. 정상적인 survival=true 역공과 위험 없는 짧은 공격은 기존 자동 테스트로 별도 검증했다.

## 검증

위험 중 비생존 짧은 공격의 신규 시작·유지 회귀 테스트를 추가했다. 기존 정상 생존 역공과 위험 없는 공격도 통과했다. 전체 테스트 첫 실행의 궤적 pin2개와 과거 ESCAPE 사례는 행동 변경으로 달라져 fixture를 갱신했다. 소유권·실제 점령·벽 사망0·성공 부활 조건은 유지했다. 새 R22 궤적은 점령137/108회, 성공 부활5/12회이고 벽 사망0이다.

ESCAPE 사례는 현재 성격·특성 배정으로 R28/14봇/seed73을 정상 이동 재생해 tick5114에 찾았다. 별도 이동 분기가 tick5115에 실제 선 접촉 절단과 안전 귀환을 완료했다. 상태나 봇 목표를 주입하거나 기존 안전 주장을 약화하지 않았다.

Classic 계측 비간섭 테스트는 두 경기의 실제 재생에 약104초가 걸려60초 제한을 넘었다. 별도의 부활 없는 대조군 검사도 약74초가 걸려 같은 제한을 넘었다. 두 테스트의 경기 길이와 모든 조건은 유지하고 실행 제한만180초로 조정했다. 최종 실행에서는 각각154.4초와12.5초로 통과했다. 다른 작업의 테스트도 같은 PC에서 실행 중이어서 실행 시간의 변동이 컸다. 게임 안전 기준이나 audit 합격 기준 변경은 아니다.

전체 Vitest 최초 실행은600개 중596개 통과였다. 갱신한 fixture가 있는 세 파일 재검증은15개 중14개 통과, 마지막 Classic 파일 재검증은4개 모두 통과했다. 파일과 테스트 이름으로 최신 결과를 합친600개 전부 통과를 validation.json에 기록했다. 한 번의 전체 실행이600개 모두 통과했다고 주장하지 않는다.

타입 검사(npm run typecheck)와 클라이언트 production 빌드는 통과했다. 기존 큰 번들 경고는 남아 있다. PC HUD 검사7개 중5개 통과,2개는 시간 초과였다. 같은60초 제한과 같은 검증 항목으로 해당2개만 다시 실행하여 둘 다 통과했다. 닉네임 선택·따라보기·사람 없는 관전·원한 원인·피해/예상/실제 되찾기·재배치 경로/도착/종료·production HUD 비활성을 확인했다. 화면도 직접 확인했다. 모바일 검사는 요청 범위에 포함하지 않았다.

## 이번 관전 체크리스트

이번 수정의 핵심은 위험 중 공격과 귀환·회피의 우선순위다. 내 선을 밖에 남긴 상태에서 상대 머리가 그 선에 접근하는 장면을 고른다. 상대가 내 영토를 뜯는 것만으로 이 안전 분기가 켜지는 것은 아니다.

|볼 점|기대하는 모습|기록할 이상 징후|
|---|---|---|
|위험 중 무리한 맞공 제한|봇 행의 `위험 위험` 표시가 켜질 때, 생존 역공 자격이 없는 짧은 공격을 대신해 `ESCAPE` 또는 `RETURN`으로 전환한다. 최근 판단/안전 개입에 `DANGER`가 나타날 수 있다.|위험한데 비생존 `ATTACK`을 계속 유지하거나, 회피와 공격을 반복하며 귀환을 늦춘다.|
|공격 기회 유지|위험이 낮을 때 정상 공격 장면이 남고, 자격을 충족한 생존 역공도 가능하다. 모든 후보에 공격할 필요는 없다.|여러 안전한 기회를 지나도록 계속 회피만 한다. 성격·특성과 함께 기록한다.|
|사망 전 행동|사망 직전 공격 유지·귀환·회피 중 어느 상태였는지 확인한다. 회피를 선택한 뒤에도 상대가 선을 먼저 끊을 수 있다.|사망만으로 이번 수정 실패를 단정하지 않고, 선택과 전환 순서를 남긴다.|

먼저 seed137을 본다. 이전에 엉킨 #0·#4·#9 주변 장면과 tick3000~4500은 참고 범위다. 수정 이후에는 이전 판단부터 경기 궤적이 바뀌어 같은 tick에 같은 싸움이 나타날 필요는 없다. 세 봇이 동시에 엉키는 장면을 기다릴 필요도 없다. 일반적인 두 봇의 선 접근 장면으로 판단할 수 있다.

다음으로 사망이 각각2회 증가한 seed19 또는101을 본다. 증가 자체를 이번 수정의 인과관계로 단정하지 않고, 죽기 전에도 공격을 유지했는지, 회피로 전환한 뒤 선이 잘렸는지 나눈다.

HUD에서는 봇 행의 위험·목표, `생존 역공 예/아니오`, `최근 판단 tick`, `최근 상태 전환`을 함께 본다. `pressure`는 감정 지표이며 이번 `danger` 분기의 표시와 구별한다. `현재 계획을 세운 판단`은 과거 계획의 이유이고 `PLAN_CONTINUE`는 실행 중일 수 있다. 서로 다른 판단 시점의 표시를 섞어 한 번의 화면만으로 위반을 확정하지 않는다.

일단 위험 중 회피와 일반 공격 장면을 각각2~3회 확인하면 1차 관전 피드백을 남길 수 있다. 생존 역공은 드문 예외이므로 안 보인다고 실패는 아니다. 이 관전 횟수는 수동 확인의 시작 기준이며 자동 audit의 사망·성장·비용 재검토 기준을 대체하지 않는다. 기존 원래 기준군 대비 사망+21.3%와 비용 판정 유보,3단계 보류는 유지한다.

이상 장면은 `seed / 피해 또는 선택 봇 #번호 / 상대 #번호 / tick 범위 / 마지막 상태와 죽음 여부`로 남긴다. 정확한 순간을 못 잡으면 tick 범위로 충분하다. 예: `137 / #9 / 상대 #4 / t3300~3500 / ATTACK→ESCAPE, 이후 선 절단으로 사망`. 이 예시는 기록 형식이며 실제 새 경기 관전 결과가 아니다.

2026-10-12 관전 재현에서 #7의 첫 선 접촉 사망을 고정하고 [확장 출발 안전 조건표](bot-ai-phase025-launch-safety-proposal.md)를 작성했다. 아직 승인 전 제안이며 행동 코드는 e4e2f08 그대로다.
