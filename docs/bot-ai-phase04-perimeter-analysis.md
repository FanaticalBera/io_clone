## 중단 뒤 실제 결과

모든 guard1404개의 이후2초 창을 같은 생명 안에서 추적했다.1390개는 완전2초,1개는 그 안에 사망,나머지는 창 끝 등으로 잘렸다.1176개 창 안에서 해당 봇의 실제 CAPTURE가 발생했다. 포획 이벤트는lifeId가 없으므로 같은 시뮬레이션 step의 실제 참가자 생명과 연결했다. 외부 선 노출383개의 guard 순간에는 모두 실제 선이 있었다.

이 수치는 ‘같은 봇이 이후 점령했다’는 관측이다. 원래 중단 계획의 완료/수익이나 순수 손실 회복으로 계산하지 않는다. 여러 guard의2초 창이 겹쳐 같은 CAPTURE를 포함할 수 있으므로 획득 칸을 합산해 guard의 효과로 만들지 않는다. 안전 회피 후 사망이 적다는 것도 guard를 약하게 해도 된다는 근거가 아니다.

## 한 가지 수정 제안 — 선택 전에 같은 벽 예측 적용

제안 범위는 **EXPAND/STEAL 후보를 실제 선택하기 전에 기존 PERIMETER_GUARD의 조건을 확인**하는 것 하나다. 점수 순서 후보에서 실제 첫 조향을 계산했을 때 같은tick에 guard override가 발생할 후보를 건너뛰고 다음 기존 후보를 확인한다. 이는242건의 선택 직후 폐기를 겨냥하며 전체1042건을 없애겠다는 제안이 아니다.

현재셀 radius≥map.radius−2의 기존 검사 띠에서만 수행한다. 경로를 복사해 현재 waypoint 소비·reach·look-ahead와 동일한 `departureIntent(..., ownedPatrol=false)`로 실제 첫 intent를 구하고 기존 `perimeterEscapeDirection`을 그대로 사용한다. 새회전율·예측시간·벽임계·가산점·RNG·계획유지/대기·재배치 규칙을 넣지 않는다. ATTACK/RETURN/REPOSITION에는 이 후보 필터를 확대하지 않으며 기존 매tick guard는 그대로 남긴다. 통과 후보가 없으면 현재 기존 fallback을 따른다.

이 문단은 기준 분석 당시의 제안이다. 2026-10-13 사용자 승인 후 이 수정 하나를 구현했으며 최신 결과는 [선택 전 벽 검사 검토](bot-ai-phase04-wall-selection-review.md)에 기록한다. 적용하면 미래 동선/RNG 소비가 달라질 수 있으므로 중거리 기존 성공13개 새 손실0,known seed1,확장1,024개,자연8시드 보유/사망/공격/성격/비용을 전후 비교한다. 비용은 observer 없는 같은 세션에서 측정하고 기존+20% 재검토 기준을 유지한다. 사망 증가나 벽 사망을 성장이 상쇄한 것으로 자동 통과시키지 않는다.

승인 후 **이 수정 하나만 적용 → 자동 회귀 확인 → 실제 사람이 봇과 플레이** 순서다. 사람 플레이에서는 seed19·137을 중심으로 가장자리 확장 재개,같은 방향 반복 취소,안전지킴이의 소극화,평범한 공격/되찾기를 본다.14봇 관전만으로 사람 플레이를 대신하지 않는다. 사람 테스트 전후로 두 번째 보완을 끼워 넣지 않는다. 그 결과를 받은 다음(a)/(c) 우선순위를 다시 정하며,확장audit의 낮은 성공률만 보고 지금(c)를 앞당기지 않는다.
