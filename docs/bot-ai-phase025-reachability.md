# REPOSITION 경계 도달성 필터 순서 수정

2026-10-10. 사용자 승인한 후보 누락 수정 구현·동일 상태 검증 완료. **균형은 재검토 필요**다. 원래 기준군 사망 94→115회(+22.3%)로 +20% 재검토 기준을 넘었다. 3단계·P/D/V 튜닝·공격/안전 기준 변경은 진행하지 않았다.

## 수정 범위

수정 전에는 피해 시각/가중치/ID로 경계를 정렬해 최대 8개로 자른 뒤 거리 조건을 검사했다. 이제 자기 영토 안의 BFS를 20칸 깊이까지만 한 번 실행해 거리를 구한다. 11–20칸으로 닿는 경계만 추린 뒤 같은 정렬 기준으로 최대 8개를 평가한다. 선택 경로는 기존 shortestPath를 사용하므로 경로 동률 순서와 남은 안전 검사는 유지된다. 개별 경로 평가/호출은 최대 8개이고, 모든 경계마다 별도 BFS를 실행하지 않는다.

거리 11–20칸·P>0·P 식·현재/다음 3개 경유 칸의 관측 머리 거리 ≤2 차단·봇 전체 6초 대기·8초 제한·관측 12칸·원한/피해 자격·D/V 상한·V=0·기존 경계 6+2·공격/예약/이동/점령/부활 규칙은 유지했다. RNG를 추가로 소비하지 않는다. 가까운 안전한 D 계획을 먼저 고르는 별도 제안은 적용하지 않았다.

HUD의 10칸 이내/20칸 내 경로 없음은 이제 **전체 피해 경계에서 거리 필터로 제외한 수**다. 최대 8개는 필터 뒤 점수·안전을 평가한 수이며, HUD 문구를 구별했다. 필터 집계가 커져도 유효 후보의 LOW_PRIORITY 이유가 사라지지 않게 판정을 유지했다.

## 기능 검증과 비용

최종 전체 Vitest **598개 모두 통과**(단일 워커, 기존 timeout 유지), 관련 40개 재검사도 통과했다. 타입 검사·실험 스크립트 strict 검사·빌드·PC Playwright 7개 모두 통과했다. HUD on/off 판단·RNG·월드·디렉터 예약 순서, 관측 밖 상대 정보 비사용과 원래 안전 조건을 확인했다. 초기 전체 Vitest 598개 중 4개 불일치를 확인했다. R22 고정 핀 2개는 실제 점령·소유권·벽 사망 0·성공 부활 조건을 유지하고 갱신했다. 진단 fixture는 초기 성공 회수가 마지막 6개 HUD 기록에서 밀려난 것이었으며, 900tick 재현 구간의 모든 종료 사건을 관측하도록 바꿨다. 실제 누적 회수 8칸과 사망 0, HUD on/off 동일은 유지했다. ESCAPE 반례는 현재 런타임의 성격 배정/개인 시드/공정 관측으로 정상 이동을 실행해 seed 19/tick 5788에서 찾았고 별도 실제 이동 분기에서 5793에 절단·자기 땅 생환을 확인했다. 상태/goal 주입과 안전 조건 완화는 하지 않았다.

관측 수집을 끄고 같은 PC에서 8시드×3라운드, 실행 순서를 번갈아 측정했다. seed 19 워밍업은 갈래별 1회 제외했고 다른 audit/검사를 병렬 실행하지 않았다. 모든 48배치의 tick 수·사망이 각 audit과 일치했다. 라운드 평균 ms/tick은 이전 3.731 / 2.993 / 2.946, 수정 4.364 / 3.046 / 2.952다. 중앙값 **2.993→3.046ms(+1.8%)**로 +20% 비용 재검토 기준 안이다. 초기 라운드 변동과 새 대전의 처리 부하 차이가 있으므로 알고리즘 자체의 효율 변화로 해석하지 않는다. 같은 시드별 샘플은 요약에 보존했다. 관전 브라우저 등 데스크톱의 주변 부하는 통제하지 않았다.

## 현재 판단

후보 누락 수정의 기능은 확인됐다. 하지만 원래 기준군 대비 사망 재검토 기준과 성격 수렴 문제가 남아 있으므로 전체 2.5단계 합격이나 3단계 착수를 선언하지 않는다. 추가 튜닝은 적용하지 않고 seed 137과 재배치 후 새 확장의 사망 원인을 후속 검토 대상으로 남긴다. master 반영/push 없이 실험 브랜치에 저장한다.
