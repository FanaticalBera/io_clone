# 봇 AI 2.5단계: 묶음 ①·② 결과

2026-10-10. 상태: **①·② 구현·자동 검증 완료 / 사망 증가 재검토 필요 / 사용자 관전 대기**. [승인 수치와 ③ 보류 설계](bot-ai-phase025-proposal.md)를 따른다. ③ REPOSITION과 3단계는 구현하지 않았다. 실험 브랜치는 `codex/bot-ai-phase01`이다.

최신 검토: [8시드·다섯 갈래 원인 분리 결과](bot-ai-phase025-ablation.md). 사망/계획 귀속을 보강했으며 단일 제안은 V=0, D 유지다. 성격 수렴이 남아 2.5단계 합격이나 다음 단계 승인으로 처리하지 않는다.

## 승인 조건과 실제 변경

REPOSITION 재시도 대기는 **봇 전체 6초**로 설계에 수정했다. 두 가해자가 반대쪽에서 뜯는 A→B→A의 실제 왕복을 대상으로 하는 지표 정의도 남겼다. 현재는 이동 상태가 없으므로 재배치/왕복 횟수를 측정했다고 주장하지 않는다.

같은 칸이 되찾기 D와 복수 V에 동시에 포함되는 것은 의도된 동작이다. 두 raw를 합친 뒤 **최대 +6점 및 완성된 기본 후보 점수의 50%**로 제한한다. HUD에 D/V·raw·적용 가산·중첩 칸 수를 표시한다.

- 공개 소유권을 옮기는 당시의 가해자·피해 칸 ID를 보존한다. 전역 피해는 원한/구역 기억에 기록하고 당시 근처 피해 수만 pressure에 쓴다. A→B→C에서 A의 최초 가해자를 C로 바꾸지 않는다. 머리·선·방향의 관측 범위는 그대로다.
- 상대별 최근 10초 피해가 6칸이면 원한 +3을 한 번 적립하고 모두 소비한다. 2초 대기 중 피해는 누적에서 제외하되 구역/HUD에 남긴다. 원한은 유지하지만 미적립 피해와 구역은 자기 사망/부활 때 초기화한다.
- 구역 반감기 20초/수명 60초, 상대별 32칸/전체 96칸을 적용한다. 기억 한도로 실제 피해 수를 자르지 않는다.
- 경계 후보는 일반 4개와 도달 가능한 피해 경계 최대 2개, 중복/빈자리는 가까운 경계로 채운다. 피해가 없으면 기존 6개를 유지한다. 내부 접근 10칸과 전체 경로 24칸, 모든 기존 안전 검사·성격별 루프/선 한도는 유지한다.
- 가산점은 현재 머리 주변 12칸 안에서 실제로 되찾을 피해 칸과 원한 상대가 현재 소유한 칸에만 적용한다. 공격 확률·공격 거절 조건·공통 근접 루프·특성 범위 절단은 튜닝하지 않았다. 추가 행동 RNG 추첨도 없다.

## 실제 이동 검증

[실제 이동 fixture](../tests/bot-damage-fixture.ts)에서 B가 A에게 **4칸씩 두 번** 탈취한다. 두 점령 모두 6칸 미만이지만 합계 8칸으로 원한 +3이 쌓인다. B가 자기 영토를 통해 물러난 안전한 기회에서 안전지킴이+영토집착 A가 피해 쪽 계획을 선택하고 실제 이동·점령으로 **8칸을 되찾는다**. 두 봇 사망 0, 전체 경로/선 한도 유지다. 초기 판 배치와 두 봇의 준비 경로는 통제했고, 탈취/대응/점령은 공유 이동 엔진으로 실행했다. 자연 대전의 보장 확률로 해석하지 않는다.

## 0384f9a와 같은 조건의 비교

R56, 스폰 7칸, 14 BOT, 안전 부활, 동일 성격·특성/행동 배정 시드, 클래식. seed 4·19·73 각 120초다. 순영토 증가에서 사망 중립화와 부활 지급은 제외한다. 근거는 [요약](../evidence/bot-phase025/summary.json), [기준](../evidence/bot-phase025/baseline-response.json), [①만 적용](../evidence/bot-phase025/bundle1-response.json), [①·② 적용](../evidence/bot-phase025/response.json), [실행·소스 식별](../evidence/bot-phase025/manifest.json)에 보관했다.

| --- | --- | --- |
| 순영토 증가 | 20,849 → 21,196칸 | +1.7% |
| 총 점령 | 27,724 → 27,153칸 | −2.1% |

되찾기/탈취는 tick 전후의 공개 소유권 표본이다. 같은 tick에 점령되었다가 사망으로 중립화된 칸은 누락될 수 있다. 동일한 집계 방법으로 비교하며 가산 후보 수를 되찾기 성공으로 세지 않는다.

| seed | 사망 | 총 점령 | 순영토 증가 |
| --- | --- | --- | --- |
| 4 | 16 → 15 | 9,088 → 9,165 | 7,732 → 6,920 |
| 19 | 7 → 14 | 9,152 → 9,079 | 6,592 → 6,942 |
| 73 | 5 → 14 | 9,484 → 8,909 | 6,525 → 7,334 |

**사망 합계는 승인된 +20% 재검토 기준을 넘었다. 밸런스 합격이나 다음 단계 진행으로 처리하지 않는다.** seed 4는 16→15로 줄었으나 seed 19는 7→14, seed 73은 5→14로 늘었다. seed 4의 순영토 증가도 줄었다.

①만 적용한 격리 사본은 세 시드 모두 기준과 **매 tick 입력·소유권·선·머리 위치/방향·생명 상태 궤적 해시가 같았다**. 이 표본의 변화는 ②를 추가한 대전에서 나타났다. 확장 경계 선택과 가산점 각각의 기여까지 분리한 결과는 아니다.

①·②의 사망 43회 중 37회는 ESCAPE 중이며 그중 33회는 기존 선 접촉, 3회는 같은 tick의 새 선 접촉, 1회는 귀환부 점령이었다. ATTACK 중 사망은 1회다. 이를 원한에 의한 직접 머리 추격 사망 증가라고 단정할 수 없다. 피해 방향의 확장이 교전·선 노출·귀환에 미치는 영향을 관전에서 재검토한다. 기존 안전 검사 통과와 향후 상대 이동에 대한 생존 보장은 별개다.

## 성격과 공격 거절: 보고만

탈취 비중은 tick 표본의 다른 참가자 소유 → 자기 소유 칸 / 총 점령이다. 평균 외부 길이는 선택된 계획의 값이다. 실제 경로가 모두 그대로 실행되었다는 뜻은 아니다.

| 성격 | 탈취 비중 기준 → 적용 | 계획 평균 외부 길이 기준 → 적용 |
| --- | --- | --- |
| 영역탐험가 | 7.4% → 13.1% | 13.70 → 13.18칸 |
| 선사냥꾼 | 17.2% → 13.7% | 9.64 → 8.96칸 |
| 안전지킴이 | 16.7% → 10.9% | 7.80 → 8.30칸 |
| 영역도둑 | 28.8% → 22.8% | 11.03 → 10.44칸 |

| 성격 | 적용 뒤 공격 거절 상위 3개 |
| --- | --- |
| 영역탐험가 | NO_APPROACH 1,460회 / VICTIM_RETURNS_FIRST 660회 / TRAIL_BUDGET 192회 |
| 선사냥꾼 | VICTIM_RETURNS_FIRST 1,675회 / NO_APPROACH 1,548회 / TRAIL_BUDGET 445회 |
| 안전지킴이 | NO_APPROACH 3,067회 / VICTIM_RETURNS_FIRST 349회 / TRAIL_BUDGET 45회 |
| 영역도둑 | NO_APPROACH 1,078회 / VICTIM_RETURNS_FIRST 857회 / TRAIL_BUDGET 167회 |

집계 단위는 판단에서 관측된 공격 후보 검사다. 같은 판단의 slot/cell/interrupt/reason이 모두 같은 항목은 한 번만 센다. 계획 생성/변경과 실행 중 판단, SELECTABLE/선택되지 않음/선택 ATTACK은 원시 결과에서 별도로 보고한다. 서로 다른 선 칸이나 interrupt 여부는 별개 검사이며 단일 상대 수·공격 에피소드 수와 같지 않다. 후보가 없는 판단도 분모에 남긴다.

후속 공격 조건 검토를 하나만 한다면 **NO_APPROACH 경로 실패를 먼저 분해**하는 것이 우선이다. 경로가 없는 경우와 길이/회피 조건에 막힌 경우를 구분하고, 안전한 접근을 실제로 놓치는 사례가 확인된 조건 하나만 제안한다. 선사냥꾼에서는 VICTIM_RETURNS_FIRST도 많지만 죽이기 전에 상대가 귀환한다는 안전 기준을 빈도만 보고 완화하지 않는다. 이번에는 아무 공격 조건도 바꾸지 않았다.

움직임은 목표별 점유 시간, 모양/외부 길이, 실제 내부/외부 칸 이동, 근접 작은 루프 비율과 목표 분포의 total variation을 보고한다(0이면 같은 목표 비율, 1이면 완전히 다른 분포). seed 73의 영역탐험가↔영역도둑 목표 분포 거리는 **0.172→0.024**로 가까워졌다. 모든 성격이 시각적으로 더 구별된다고 주장하지 않는다. 실제 공간 경로가 같다는 의미도 아니다. 근접 상황의 300개 선택 확장 모두 외부 길이 6칸 이하였으며 공통 안전 루프 효과가 남아 있다. 이 항목은 측정만 했다.

## 자동 검증과 성능

타입 검사, Vitest **84파일/565개**, 빌드, PC 관전 Playwright **5개** 통과. 누적 10초 경계·2초 대기·초과 소비·중복·재탈취·혼합 근처/전역·A→B→C·중립화/이탈/사망·32/96칸 한도·감쇠/만료·D/V 중첩/상한·관측 밖 머리/선/의도 비간섭·가까운/먼 경계·실제 이동 되찾기·위험 후보 거절을 확인했다.

기존 HUD 수집 켬/끔의 실제 입력·판단/구역 기억·행동 RNG·디렉터 예약 순서 일치 검사가 통과했다. 기존 사망·점령·리스폰·예외 공격 검증도 유지했다. 의도된 행동/기억 변경으로 고정 궤적 해시 2개를 재기록했으며 소유권·실제 점령·벽 사망 0·성공 부활 검사는 유지했다. 기존 ESCAPE 증거는 새 정상 대전 seed 15/tick 5114에서 다시 확보했고 실제 선 절단/생환 분기 검사를 유지했다. 경기 종료 뒤 탐색이 진행하지 못하는 fixture 루프도 종료하도록 고쳤다.

동일 PC에서 다른 검증 작업 종료 후 순차 실행, 워밍업 1회 제외·1,800tick × 3회 중앙값은 **기준 2.903ms/tick, 적용 2.717ms/tick, HUD 수집 포함 3.031ms/tick**이다. DOM/렌더 비용은 포함하지 않는다. 행동 궤적과 표본 부하가 달라 작은 차이를 알고리즘 성능 향상으로 주장하지 않는다. 승인된 +20% 비용 재검토 기준은 넘지 않았다. ## 사용자 관전에서 결정할 것

개발 서버에서 새로고침 후 14봇 관전을 다시 시작한다: `http://127.0.0.1:5180/?debug=1&spectate=1&experimentSeed=19`.

1. 작은 탈취가 원한 누적으로 설명되고, 안전한 기회에서 피해 쪽 확장과 실제 되찾기가 나오는지 본다.
2. seed 19/73에서 피해 쪽 진입 뒤 노출 선이 잘리거나 귀환이 늦어지는지 본다. 사망 증가를 먼저 재검토하며 승인 수치는 임의로 바꾸지 않았다.
3. 원한/피해 구역은 남지만 선택 계획의 `내부 10칸으로 도달 불가 경계`가 계속 남고 반대쪽 확장만 하는 장면을 확인한다. audit의 도달 불가 경계 합계는 반복 판단 표본이며 독립 사건 수가 아니다.
4. 먼 피해 구역으로 인해 대응하지 못하는 장면이 실제로 남을 때만 ③ REPOSITION을 진행한다. 봇 전체 6초 대기와 두 가해자 왕복 지표 설계는 보존한다. 도달 불가 수치만으로 자동 착수하지 않는다.
