# 확장형 대면 정책 채택·공유 APK

2026-10-15. 사용자가 B(`explorer-commit`)를 일반 앱에 적용하고 master에 병합·push한 뒤 상대방에게 전달할 APK를 만들도록 승인했다. 첫 비교의 원본은 [대면 실험 기록](bot-duel-encounters.md), 소스·결과 요약은 `evidence/bot-duel-encounters/summary.json`에 보존한다.

## 채택 내용

가까운 상대 앞에서 확장형도 작은 영토 탈취·복귀만 반복하던 행동을 줄인다. 확장형의 공통 근접 축소 경로와 예정 외부 길이 기반 귀환 제한을 해제한 B를 채택했다. 실제 노출 꼬리 위협·출발 차단·귀환 경로·벽 회피는 유지한다.

사용자는 숙련자 한 판 시연에서 이전보다 훨씬 낫고 일부 얄미운 성격이 남아 있는 점이 좋다고 평가했다. 기록은 약 2분43초·14.3%·6킬이며, 이전 체감 5분·3~4킬과 구분한다. 반복 통제 실험이나 난이도 통계는 아니다. 사용자는 봇의 실수와 사망 증가를 허용하고 사람의 공략 재미를 우선하는 방향을 선택했다.

- 확장형 전체에 적용. 큰 육각 싱글 13봇의 배정에서는 보통 3~4마리이며 개별 한 마리의 수정이 아니다.
- 선사냥꾼·안전지킴이·영역도둑의 고유 판단은 유지한다. 변화한 확장형과의 상호작용으로 다수전의 결과는 달라질 수 있다.
- 코인·부활·이동/충돌/복귀 판정·속도·모드·맵·마커·효과·UI는 변경하지 않는다.
- `createGameplayBotMemory`를 싱글 Practice, 공유 RoomManager의 초기/대체 봇, RoomLoop의 누락 메모리 복구에 사용한다. LAN 방장과 서버가 같은 정책을 사용한다.
- HUMAN 백그라운드·연결 끊김 return-only는 원래 `createBotMemory`로 생성한다. raw AI 역사 비교 fixture도 그대로 남긴다.
- `rooms.ts`에서는 봇 메모리 생성 함수만 바꿨다. 기존 맵 선택·방 권한·슬롯·프로토콜 9를 보존했다.
- `dist`는 최신 소스에서 다시 생성해 정책과 관련 생성 경로의 서버 모듈 및 웹 번들을 갱신했다.

## 검증

실험 정책 자체의 대면·8시드 다수전·CPU·진단 비간섭 비교는 원본 보고서를 따른다. 이번 채택은 같은 B를 일반 생성 경로에 연결하는 변경이다.

- 접촉/중립 간격 양쪽에서 gameplay 기본 생성과 명시적 B의 입력·궤적·RNG·추격 예약 일치.
- 확장형 외 성격의 gameplay 생성과 raw 기준 궤적·RNG·예약 일치.
- 큰 육각 R56/14와 작은 육각 R24/4의 실제 Practice 기본값이 명시적 B 참조 시뮬레이션과 상태·다음 RNG 일치.
- 실제 LAN 2인/12봇의 기본 활성화와 기존 6종 맵·복귀 판정·즉시 스냅샷 전달 확인.
- RoomManager 초기 생성·퇴장자 대체·EXPAND 메모리 복구와, 배경 HUMAN을 포함/제외한 RoomLoop 참조 일치 확인.
- 관련 통합 검사 4파일·48개 통과. client/server/tests 타입, 서버·웹 빌드, 오프라인 APK 웹 빌드·Capacitor sync·Android Gradle debug 빌드 통과.
- 최종 전체 검사와 원격 commit 정보는 `evidence/bot-duel-encounters/release.json`에 기록한다. 첫 병행 전체 검사에서는 상태·RNG 참조 비교 한 건이 기본 20초 제한에 걸렸고 assertion 실패는 없었다. 앱 코드는 바꾸지 않고 자체 빌드가 없는 단일 워커·테스트 제한 60초로 전체를 다시 확인했다. 이 제한은 테스트 실행 설정이며 게임 성능 기준이 아니다.

작은 육각의 봇 사망 증가는 알려진 변화이며, 실수 허용에 관한 사용자 결정과 함께 유지한다. 이번 배포 과정에서 장시간 기기 발열이나 새 APK로 두 실기기 LAN을 다시 측정한 것은 아니다.
