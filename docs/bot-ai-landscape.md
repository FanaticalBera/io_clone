## 사망 진동과 손을 유지한 부활 조작

전투 진동은 기존 저장 키 `killVibration`을 그대로 사용한다. 처치 패턴 `[35,20,55]`와 사망 패턴 `[90,40,120]`을 구분한다. 확정 DEATH event cursor에 연결해 반복 snapshot/재연결의 과거 사건을 다시 진동시키지 않는다. 한 snapshot에 내 처치와 사망이 동시에 있으면 사망 진동을 우선한다. API 지원·사용자 활성화·화면 표시·설정 off 검사는 그대로 적용한다.

기존 `input.enabled=false`는 reset을 호출해 사망 때 held pointer capture도 잃었다. 사망/등장 대기만 별도 `suspendForRespawn()`으로 방향 송신을 중단하고 primary pointer 추적을 보존한다. 대기 중 drag anchor/trackpad last point는 최신 손 위치로 갱신해 이동을 누적하지 않는다. 조이스틱은 흐리게 표시하며 pointer capture와 현재 손 위치를 보존해 새 lifeId의 초기 방향 설정 이후 재적용한다. release/cancel/lost capture/blur/resize/settings/mode 변경/leave는 이전처럼 gesture를 지운다.

`tests/e2e/respawn-touch.spec.ts`는 정상 온라인 스폰에서 실제 CDP touch를 누른 뒤 서버의 실제 직진으로 WALL_HIT를 일으키고, 정상 3초 대기/tryRespawns 이후 손을 한 번도 떼지 않은 상태로 drag/trackpad/joystick을 조작한다. 인간의 position/ownership/trail이나 markDead를 직접 설정하지 않는다. 새 생명 방향이 서버 입력에 전달되고 위치가 움직이는지, 사망 진동 정확히 한 번인지 확인한다. `tests/e2e/input.spec.ts`는 대기 중 송신 없음·이동 누적 없음·대기 중 손을 뗐으면 부활 뒤에도 해제 상태인 것을 추가로 검사한다. 실제 S24 촉감/편안함은 사용자 재인수 대상이다.

## 애매한 사망 판정 조사와 중간 반경의 공격 기회

사용자는 둘러싸거나 점령하지 않은 것처럼 보이는 순간의 사망과 중간 반경 확장/노출 기회 무시를 보고했다. 해당 플레이의 기록은 없으므로 그 장면의 원인을 확정하지 않는다. 정상 스폰, 방향 입력, `stepMatch()`를 사용하는 8개 시드×8봇/2인간+6봇, 각 3,600tick으로 조사했다. `watchDeaths()`는 정리 전 상태를, `watchCaptureResolution()`은 동시 점령의 원래 선과 점령 교차를 기록한다. 사망마다 선/mask 및 영토/count 일치, 직접 접촉 위치, 점령한 선, 끊긴 출발 연결, 벽의 실제 교차점, 사망 사건 1회, 대기 중 위치 정지/선 제거를 확인했다.

`scripts/death-audit.ts` 및 `evidence/death-cause-audit.json`: 16경기·370회 사망에서 위 조건 위반 0회. 직접 선 접촉 344회(그중 현재 칸에서 막 생성되는 선 접촉 18회), 출발 연결 상실 14회, 점령 영역의 선 절단 1회, 벽 11회다. 벽 사망은 사람이 조작하는 두 경로의 일부 배치에서 발생했으며 8봇 경기에서 발생하지 않았다. 이것은 보고된 실제 장면에 버그가 없다는 보장이나 독립적인 전체 규칙 증명은 아니다.

기존 규칙은 통과한 육각 칸 전체가 선 판정이다. 본체끼리 닿지 않아도 떨어진 선을 밟으면 사망하고, 동시에 영토 밖의 같은 칸으로 들어와 생성 중인 선을 접촉해도 절단된다. 자기 영토 안의 본체만 겹치는 경우는 기존 규칙대로 별도 사망을 만들지 않는다. 이번에는 죽음 판정·동시 사건 순서·kill 우선순위를 변경하지 않고 원인과 해당 칸을 기존 `TRAIL_CUT`에 부가했다. snapshot에 선택적 `deathContext`를 전달해 UI가 직접 접촉/점령 선 절단/출발 영토 상실을 구분한다. 피해자의 context는 전체 사망 대기 동안 보존하고 정상 respawn에서 지운다. 이벤트/참가자 context는 public view에서 복사하고 프로토콜은 원인과 칸 범위를 검사한다. 과거 context 없는 snapshot도 호환된다.

봇의 실패는 실제 중간 루프에서 재현했다. 이전 판단은 상대가 계속 바깥으로 움직여도 즉시 최단거리로 귀환한다고 가정했다. 예를 들어 방어형의 5칸 선 루프에서 `VICTIM_RETURNS_FIRST`만 반복하며 공격하지 않았다. 수정 후 같은 정상 이동 루프에서는 선 3칸일 때 공격해 tick 41에 직접 절단한다. 더 큰 반경의 7칸 선 루프도 이전에는 무시했고, 수정 후 선 6칸/tick 54에서 절단한다. `scripts/medium-attack-audit.ts`, `evidence/medium-attack-before.json`, `medium-attack-after.json`에 현재 판단 trace와 이동 샘플이 있다.

- 상대의 관찰된 목표가 귀환 방향이면 기존 보수적인 예상 시간을 유지한다. 그렇지 않으면 관찰된 진행을 최대 0.5초만 예상한 후 귀환 시간을 다시 계산하며, 즉시 귀환 예상보다 최대 0.5초만 더 허용한다. 200ms마다 선이 닫혔는지 재평가하고 실제 상대 입력의 미래는 읽지 않는다.
- 자기 영토에 인접한 상대 선도 침범으로 평가한다. 4칸 이내·1.25초 이내의 유리한 공격 기회는 선 길이와 성향의 임의 확률에 막히지 않는다. 상대가 이미 귀환 중이거나 내 기존 선을 먼저 끊는 공격은 계속 거절한다.
- 짧은 counter-cut/안전 RETURN 우회는 1.25초 도달과 자기 선 한도 및 귀환 우회 최대 0.85초를 확인한다. 이미 진행 중인 ESCAPE는 계속 귀환한다.
- 한 상대의 긴 선으로 후보 6개가 모두 채워지지 않도록 상대별 가까운 후보 3개, 전체 최대 12개를 비교한다. `watchBotDecisions()`는 opt-in으로 선택/거절 이유와 상태 전환을 남긴다.

`tests/core/medium-attack.test.ts`는 정상 스폰/실제 방향 입력만으로 네 성향과 양쪽 역할에서 짧은 루프 공격, 방어형의 중간 반경 공격을 확인한다. 영토/선/위치를 직접 만들지 않는다. 상대가 보고 즉시 방향을 바꾸면 공격이 실패할 수 있으며 모든 기회를 처치로 보장하지 않는다. 이는 규칙 기반 봇의 판단 조건 개선이고 인간처럼 장기 전략을 학습했다는 뜻이 아니다. 맵 반경 22는 사용자 선택대로 유지한다.
