# 설정창 복귀 후 움직임 저하 수정

2026-10-14. 기준 코드: `2785017`. 사용자 제보: S24+, 싱글, 설정 변경 없이 열고 닫아도 복귀 후 움직임이 덜 부드러움.

## 원인과 수정

- 싱글 시뮬레이션은 설정창에서 멈추지만 `Presentation.clockOffset`은 정지 시간을 반영하지 않았다. 복귀 후 모든 스냅샷 시간이 화면 시계보다 뒤처져, 보간 대신 최대 한 틱의 예측 위치를 매번 표시했다. 렌더 수치는 60fps여도 마커와 카메라 이동은 30Hz 틱마다 바뀌었다.
- 정지 시간만 더하는 것으로는 부족했다. `PracticeSession.setPaused(false)`가 부분 틱을 버리고 다음 rAF에서 시계를 초기화하므로, 첫 **진행한** 스냅샷에서 그 위상도 다시 맞춘다. 설정 닫기에서 재전달하는 같은 틱의 스냅샷은 이 보정을 소비하지 않는다. 온라인 시계는 계속 진행한다.
- 프레임 제한기의 예약 잔여 시간을 게임의 경과 시간으로 다시 전달하던 별도 오류를 수정했다. 예약은 실제 rAF 시간, 게임 delta는 별도 누적값을 사용한다. 주사율 전환 때 과거 smoothing 값 때문에 렌더를 추가로 건너뛰지 않는다.
- 화면 밖 마커 컨테이너의 렌더와 애니메이션 계산을 생략한다. 이름표 전체 너비, 보호막, 점프, 펄스와 이동 여유를 포함한다. 추적 대상은 항상 표시하며, 돌아온 마커의 효과는 절대 시간으로 원래 상태를 계산한다.

마커 디자인, 보이는 효과, 블러, 해상도, 60fps 상한, 봇 판단과 게임 시뮬레이션 규칙은 변경하지 않았다. 설정창 뒤 캔버스의 기존 30fps 정책도 유지한다.

## 검증

같은 시드 137, 같은 맵, 설정 변경 없음, 1초 열기 후 3초 측정 × 3회. 살아 있는 추적 대상의 카메라 위치가 달라진 프레임 비율을 실제 렌더 프레임에서 측정했다.

| 환경 | 열기 전 | 수정 전 복귀 3회 | 수정 후 복귀 3회 |
| --- | --- | --- | --- |
| PC Chromium, 832×384, DPR 1 | 100% | 49%, 50%, 50% | 99%, 99%, 100% |
| S24+ WebView, 832×384, DPR 2.8125 | 100% | 50%, 50%, 50% | 100%, 100%, 100% |

수정 전후 모두 약 60회/초 렌더했다. 이번 문제의 핵심은 렌더 횟수가 아니라 프레임 사이의 이동 보간이었다. `?metrics=1`의 읽기 전용 `renderState()`와 `scripts/perf/settings-return.mts`로 다시 확인할 수 있다.

동일 시드의 새 세계를 180초씩 연속 측정했다. 판을 중간에 초기화하지 않았으며 두 실행 모두 비충전, 열 상태 0이었다. 30초마다 최근 25초를 표본으로 삼았다.

| S24+ 3분 부하 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 평균 렌더 횟수 | 60.0/s | 59.6/s |
| 평균 JS 작업 | 274.62 ms/s | 243.87 ms/s (약 11% 감소) |
| 평균 렌더 CPU 작업 | 103.12 ms/s | 83.37 ms/s (약 19% 감소) |
| 평균 마커 갱신 작업 | 3.68 ms/s | 2.39 ms/s |
| 배터리 온도 시작 → 끝 | 32.8 → 33.3°C | 32.7 → 31.4°C |

수정 전 → 수정 후 순서의 짧은 측정이다. 밝기·주변 조건을 고정한 장시간 열 평형 실험이 아니므로 온도 차이 전체를 코드 효과로 단정하거나 장시간 발열 해결을 보장하지 않는다. 원자료: [전](../evidence/perf-settings-recovery/s24-before.json), [후](../evidence/perf-settings-recovery/s24-after.json).

- 컬링 켜기/끄기: 세 렌더 시점의 캔버스 실제 픽셀 동일. PNG 파일 바이트 비교가 아닌 디코딩한 픽셀 비교.
- 전체 단위 테스트: 106 파일, 705 통과 + 기대 실패 8.
- 봇·싱글 궤적: 8 시드 × 2 구성 × 3,600틱, 기준 궤적 16/16 동일.
- 클라이언트·서버·테스트 TypeScript 타입 검사 통과.
- `apk-perf`와 일반 `apk` debug APK 빌드 성공. S24+는 앱 삭제 없이 일반 수정 APK로 업데이트했고 홈 진입을 확인했다.
