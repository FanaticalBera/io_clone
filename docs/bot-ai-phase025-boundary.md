# 봇 AI 2.5단계: V=0과 피해 경계 추가 비교

2026-10-10. V=0 승인을 반영하고, 기존 성격별 경계 6개 뒤에 피해 경계를 최대 2개 추가했다. REPOSITION과 3단계는 보류한다. **비교·자동 검증 완료 / 사용자 관전 대기.**

후속 관전 진단: [D 계획과 실제 회수 추적](bot-reclaim-diagnostics.md). 행동은 유지하며 계획·실제 점령·처치를 분리해서 확인한다.

## 변경과 조건

`revengePerCell=0`, D=0.5, 원한 기록·공격 판정·피해 누적·성격 배율·가산 상한은 유지한다. 기존 성격별 정렬 결과의 첫 6개를 같은 순서로 보존한다. 내부 자기 땅을 통해 10칸 안에 도달 가능한 피해 경계 중 중복되지 않는 최대 2개를 7~8번째에 추가한다. 피해 경계가 없거나 기존 6개와 모두 겹치면 6개다. 위험·귀환·총 경로 24칸·선 길이·근접 머리 검사·공격 조건·판단 주기는 바꾸지 않았다.

시드 4·19·73·11·31·47·101·137, R56, BOT 14명, 스폰 7칸, 안전 부활, 클래식, 각 120초. 기준군과 기존 D만은 이전 감사 소스 해시와 8시드 궤적을 검증하고 원시 기록을 재사용했다. 새 갈래는 같은 감사 실행기로 실제 이동했다. 비용은 세 갈래를 모두 새로 측정한다. [사전 프로토콜·소스 해시](../evidence/bot-phase025-boundary/protocol.json).

판정은 이전과 같이 동일 시드의 차이에서 7/8 이상 같은 방향이고 어느 한 시드를 빼도 합계 방향이 유지될 때만 탐색적 방향 신호다. 나머지는 구분 불가이며 효과 없음과 다르다. 원시 전체 기록은 `.local/bot-phase025-boundary/`에 보존하고 [요약](../evidence/bot-phase025-boundary/summary.json)에 압축본 해시를 남겼다.

## 이전 보고서 보완

기준군 대비 기존 D만의 순영토 증가는 **55,483→59,312칸, +3,829칸(+6.9%)**다. 7/8시드가 증가했고 한 시드를 빼도 +2,513~+4,880칸으로 방향이 유지되어 사전 기준의 신호를 충족한다. 기존 D만 사망 +13.4%는 승인된 +20% 재검토 기준 안이다. [이전 보고서](bot-ai-phase025-ablation.md)에 이 비교를 추가했다.

## 검증

타입 검사와 감사/비용 스크립트 엄격 타입 검사, 빌드, PC 관전 Playwright 5개 통과. `npm test -- --maxWorkers=1`으로 **85파일/569개 통과**했다. 기본 병렬 전체 실행은 R56 HUD 비간섭 검사가 20초를 초과했지만, 단일 워커에서는 원래 검사 내용·시간 제한을 그대로 두고 통과했다. 검사 완화를 하지 않았다.

승인된 행동 변경에 따라 R22 고정 궤적 2개를 재기록했으며 실제 점령·소유권·벽 사망 0·부활 검사는 유지했다. ESCAPE 반례는 새 정상 이동 seed 5/tick 1065에서 확보했다. 실제 선 절단 tick 1077, 자기 땅 생환 tick 1092를 확인했고 공격·안전 조건은 바꾸지 않았다. HUD 유무의 실제 입력·RNG·월드·예약 비간섭 검사도 통과했다. [검증 기록](../evidence/bot-phase025-boundary/validation.json).

## 판단과 다음 확인

승인된 V=0과 경계 추가 한 가지 수정을 실험 브랜치에 적용했다. 사망(+14.6%)과 tick 비용(기존 D만 대비 +3.4%)은 승인된 +20% 재검토 기준 안이며 벽 사망은 0이다. 실제 되찾기는 두 비교에서 방향 신호를 충족한다. TV와 성격별 탈취 비중의 합계는 기준군 쪽으로 가까워졌지만 시드별 신호는 구분 불가다. 순영토 증가도 기존 D만 대비 −3.9%이며 기존 D만의 성장 신호가 새 방식에서 유지됐다고 주장하지 않는다.

자동 검증 결과상 관전을 진행할 수 있지만 성격 표현의 완전한 해결이나 다음 단계 합격은 선언하지 않는다. seed 73의 탐험가·도둑 구별과 seed 11·47의 사망 증가 장면을 먼저 확인한다. REPOSITION과 3단계는 계속 보류하며 추가 튜닝은 하지 않았다.

## 재현

이전 ablation의 고정 소스 사본과 원시 JSON이 `.local/bot-phase025-ablation/`에 있어야 한다. 원본 소스가 바뀌지 않았는지 해시로 확인한다. Node 24를 PATH에 두고:

```powershell
node node_modules/tsx/dist/cli.mjs scripts/bot-phase025-boundary.ts --prepare
node node_modules/tsx/dist/cli.mjs scripts/bot-phase025-boundary.ts --audit
python scripts/summarize-bot-phase025-boundary.py
node node_modules/tsx/dist/cli.mjs scripts/bot-phase025-boundary-performance.ts
```

프로토콜은 최초 준비 시에만 생성한다. 저장된 사본으로 감사와 비용 실행을 다시 할 수 있으며, 준비를 다시 실행해 프로토콜을 덮어쓰지는 않는다. 대전/테스트와 비용 측정을 겹쳐 실행하지 않는다. 최종 보고서는 같은 8시드의 원값·차이·합계·판정을 모두 보존한다.
