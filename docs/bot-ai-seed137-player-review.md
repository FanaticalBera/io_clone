후속 사용자 결정: seed137 관전과 직접 플레이를 마치고 B-quiet+C+안쪽 경계를 채택했다. 뒤쪽 침입자 인식은 이번에 넣지 않으며, 봇 동결 이후 성능 PRD 다음으로 재검토한다. 아래는 이전67e7807 장면과 당시 제안의 보존 기록으로, 동결을 막는 추가 구현 요청이 아니다. 최종 상태는 [봇 동결 기록](bot-ai-freeze.md)을 따른다.

현 엔진 규칙으로 설명되는 사망이다. 다만 AI가 상대의 닫히기 직전 루프가 자기 머리를 포함한다는 위험을 감지하지 못했다는 별도 한계가 드러난다. 이 분석만으로 엔진 전체가 무결하다고 판정하지 않는다.

## 공통 원인과 기존 버전 비교

1. 피해 확장 경계는 자기 땅 경로 10칸 안, REPOSITION은 11–20칸 안에서만 만든다. 그보다 먼 연결된 피해 경계로 점진적으로 접근하는 대체 전략이 없다.
2. REPOSITION을 만들지 못하면 일반 확장으로 바로 돌아간다. 높은 원한은 유효한 공격/확장 후보에 영향을 주지만, 먼 뒤쪽 피해를 향한 후보 자체를 만들지는 못한다. V는 승인된 설정대로 0이다.
3. 원한·피해 기록은 점령 승자에 의한 직접 소유권 이전에서 만든다. `pruneDisconnectedTerritory`가 추가로 중립화한 칸은 LOSS의 칸 목록과 피해 구역에 포함되지 않는다. 사망 중립화와는 다른 손실인데도 공간 기억에는 빈틈이 남는다.
4. B-quiet의 조용함 판정은 현재 보이는 상대 머리·선이 없는가이다. 관측 밖의 반복 피해를 조용하지 않은 상황으로 취급하지 않는다. 원래 6개 경계도 여전히 가까운 곳 위주이므로 열린 경계 하나만 없앤다고 문제가 해결된다고 단정할 수 없다.

master #7에서도 비슷한 유형이 존재했다. 예를 들어 t8070–9420에는 피해 구역이 33–44칸 떨어져 있고 원한이 높아도 `NO_DISTANT_DESTINATION`으로 앞쪽 확장을 이어 갔다. master에서도 t5430–5460 사이 직접 손실 외 약 210칸이 중립화됐다.

같은 시드의 버전별 경로 변화는 다른 봇의 동선과 만나는 상대까지 바꾼다. 초기 #7의 회수가 57 → 0인 사실은 기록하되, 이를 C 하나의 독립적인 인과 효과나 전체 성격의 일괄 너프로 해석하지 않는다.
