# 영토 복귀 여유 비교 — 2026-10-15

사용자는 ‘마커 몸통이 내 땅에 살짝 걸치면 복귀로 인정’하는 방향에 동의했고, 의도치 않은 조기 점령을 피하도록 작은 값부터 비교하기로 했다. 상대 꼬리 절단 범위는 별도 과제로 유지한다.

**채택 업데이트:** 사용자가 10단위가 적당하다고 평가하고 master 병합을 요청했다. 아래 6/10 비교는 실험 이력이다. 현재 소스의 일반 싱글·LAN 기본값은 side 32에서 10단위이며, 최종 검증·빌드·병합 상태는 `docs/home-return-release.md`를 참고한다.

## 현재 적용 범위

- 일반 앱·기본 웹·LAN의 복귀 기본값은 side의 10/32로, 현행 side 32에서 **10단위**다. 과거 중심 진입 비교용 테스트만 명시적으로 0을 설정한다. 사용자용 설정 UI나 URL 토글은 없다.
- S24+에 별도 **HEXHOLD 복귀테스트** (`com.hexhold.game.returntest`)를 설치했다. 최신 비교본은 이 앱의 싱글에서만 복귀 여유를 **10 world units**로 켠다(첫 비교본은 6). 사람과 봇에 같은 규칙을 적용하며, 봇 의사결정 정책은 수정하지 않았다. 새 규칙에 따라 실제 경기 결과는 달라질 수 있다.
- 일반 앱과 기존 무적테스트 앱의 패키지·데이터를 유지했다. 이번 테스트에는 죽음 면역이나 거점 보호가 없다. 마커·받침·펄스·인게임 UI도 그대로다. 테스트 앱의 홈 버튼에만 ‘복귀 테스트’를 표시한다.
- 10단위 정식 채택과 master 병합을 승인받았다. 별도 테스트 앱의 진단 수집 코드는 일반 앱에 포함하지 않는다. 최종 일반 APK와 병합 기록은 위 채택 문서를 참고한다.

## 후보 규칙

현재 side 32, 속도 4.41에서 첫 비교값 6은 타일 폭 약 55.43의 10.8%다. 경계에 수직으로 접근할 때 중심 진입보다 약 24.5ms 빠르고, 통상 게임 줌 .38에서는 약 2.28 CSS px이다. 두 번째 비교값 **10은 약 40.9ms·3.8 CSS px**의 여유다. 큰 받침 반경 40이나 마커 그림 자체를 충돌 범위로 쓰지 않는다.

자기 영토와의 거리가 여유 범위 밖에 있던 열린 꼬리가 다시 범위 안으로 들어올 때 조기 복귀를 처리한다. 이미 밴드에 닿아 있는 상태에서 출발·평행 이동할 때는 조기 복귀를 만들지 않으며, 기존 중심 진입 복귀는 계속 동작한다. 중립 칸을 순간 이동하거나 전체 틈을 안전 영역으로 만들지 않는다. 복귀하면서 기존 꼬리 칸이 점령되는 것은 기존 점령 방식과 같다.

이동 선분을 육각형 면의 바깥쪽 경계와 꼭짓점 원에 연속적으로 교차시킨다. 꼭짓점에서 범위가 더 커지는 단순 육각형 확대는 사용하지 않았다. 후보 이벤트를 기존 이동·벽·접촉 이벤트와 같은 시간순으로 처리하고, 실제 처리 시 해당 영토의 현재 소유자를 다시 확인한다. 절단이 먼저면 탈락, 복귀가 먼저면 회수된 꼬리를 나중에 밟아도 생존한다. 동일 이벤트 시각의 직접 절단 우선순위는 유지한다.
