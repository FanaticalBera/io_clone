## 봇별 비교와 해석

- bot-paired-deltas.csv는 각 비교·시드에서 **같은slot/닉네임/성격** 봇끼리의 세 지표 차이를 모두 제공한다. 동일 배정임을 확인했다.
- bot-slot-signals.csv는 같은slot의8시드 방향 집계다. 시드마다 그slot의 닉네임·성격이 바뀔 수 있으므로, 이를 특정 성격의 일관된 효과라고 해석하지 않는다. 봇별 차이는 역할과 함께 읽어야 하며, 전체 이득이 모든 봇의 이득이라는 뜻도 아니다.
- REPOSITION 최초 추가는 기존 보정 성장 +9.0%였으나 **실제 보유 시간 평균 −6.26%, 7/8 감소 신호**다. 사망 +20.2%와 함께 읽으면, 재점령을 포함한 성장과 살아서 땅을 오래 보유하는 성과가 다르다는 점이 드러난다. 이번엔 이 부분도 수정 없이 기록한다.
- 원래65034bd→현재의 보유 시간 평균 −3.62%, 최종 보유 +3.33%, 최대 점유율 −3.96%는 모두 구분 불가다. **출발 안전의 인접 이득을 누적 변경 전체의 성공으로 확대하지 않는다.**

## 행동을 유지하는 성능 개선 제안

**한 가지 제안: 확장 후보의 기존 선 길이·근접 머리 탈락 검사를 예상 점령 flood-fill보다 먼저 수행한다.** 함수 관측에서 plannedCapture가 약70.47%를 차지하고 출발 안전 평가 자체는 약2.91%였다. 따라서 출발 예측을 줄이는 안보다, 확장 계획의 불필요한 전체 맵 계산을 먼저 줄이는 쪽을 제안한다.

현재 순서는 유효·닫힌 경로 확인 → plannedCapture → NO_GAIN → 선 길이 제한 → 근접 머리 → 점수/RNG다. 제안은 **유효·닫힌 경로 확인 → 같은 선 길이 제한 → 같은 근접 머리 → plannedCapture → 점수/RNG**다.

1. 기존 external.length/성격별 trailLimit/밀집6칸 제한 및 근접 머리2칸 식과 처리 우선순위를 그대로 옮긴다. 임계값·후보 수·모양·판단 주기·출발 안전·재배치 안전은 변경하지 않는다.
2. NO_GAIN 탈락 우선순위도 보존해야 한다. 이 두 검사에 걸리는 후보에는 비소유 path 칸이 최소1개 있다. plannedCapture는 그 path 칸을 flood에서 막고 결과에 포함하므로 gain이0일 수 없다. 이 전제를 별도 속성 검증으로 확인한다. 따라서 두 검사를 먼저 해도 기존 탈락 reason이 바뀌지 않아야 한다.
3. 길이·너비·bevel·naturalClosure 등의 RNG는 기존 자리에서 그대로 소비하고, 점수 RNG도 기존과 같은 통과 후보에만 같은 순서로 소비한다. gain의 칸 목록과 순서, 위험·점수·동률·성격 가산점·예약 결과는 그대로 유지한다.
4. 예정 점령 계산의 scratch buffer와 경계 인덱스는 이미 재사용 중이므로, 버퍼 재사용을 새로운 개선으로 제안하지 않는다. 함수 내용이나 전체 맵 flood 규칙을 근사화하지 않고, 결과를 사용하지 않을 호출만 생략한다.

현재 seed19 관측에서 plannedCapture 이후 선 길이/근접 머리로 탈락한 후보는1,598/15,941개(10.02%)였다. 해당 호출을 생략할 여지가 있으나, **이 비율이 전체 비용 절감률은 아니다.** 관측 스크립트 자체도 원래 전체 궤적 해시와 일치했고, 다른 시드의 비율이나 실제 속도 개선은 아직 측정하지 않았다.

이는 안전 검사를 제거하거나 완화하는 변경이 아니다. 동일 검사로 탈락할 후보의 계산 순서만 바꾸는 제안이며, 아직 구현하지 않았다.

- 기존/새 확장 계획을 동일 snapshot에서 대조: 모든 후보의 선택·점수·탈락 reason·점령 칸 목록/순서 및 RNG 소비가 동일. 정상·반복 경로·급회전·맵 가장자리·밀집·각 성격/특성, NO_GAIN 우선순위 전제를 검증한다.
