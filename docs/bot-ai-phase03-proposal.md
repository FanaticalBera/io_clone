# 3단계 수치·구조 제안 — 승인 전, 구현하지 않음

2026-10-12 · 2.5단계 사용자 관전 승인 후 · 기준 행동 c84fc7a

2.5단계를 마감한다. master의 LAN 친구 대전·마커 변경을 실험 브랜치로 가져온 병합은 `ddda67b`다. 부모는 `fba4106`과 `960f678`이다. master 자체를 실험 브랜치로 교체하지 않았다. 동일 8시드에서 궤적, 판단 trace, 메모리, 다음 행동 RNG 값과 주요 지표가 c84fc7a 기준에 일치했다. 아래 3단계 값은 **제안**이며 승인받은 뒤 구현한다.

## 1. 이번 범위와 구현 순서

판단을 즉시 안전·전술 안전·전략 판단으로 분리하고 개인별 전략 주기, 유효한 계획의 유지, 집요함, 움직이는 귀환 후 재정비를 적용한다. 효과를 구분하려고 네 묶음을 차례로 검증한다.

|묶음|작업|비교 기준|
|---|---|---|
|3A|기존 계산·호출 순서를 그대로 둔 구조 분리. 기존 출발 안전·재배치 시작 안전 이관|병합 기준과 8시드 궤적·판단·메모리·다음 RNG·예약 순서 모두 동일|
|3B|전술 주기와 개인별 전략 주기 적용. 특성 후보·최소 유지·귀환 재정비는 기존대로|3A 대비 보유·사망·기회·되찾기·성능 비교|
|3C|유효 계획 최소 유지와 집요함 활성화. 귀환 재정비는 기존대로|3B 대비 비교. 집요함 효과는 동일 슬롯 명시 특성 실험도 별도 수행|
|3D|귀환 후 움직이는 자기 영토 안 재정비|3C 대비 비교|

3B 이후 행동 해시가 이전 단계와 다른 것은 예상되는 변경이다. 대신 각각의 HUD/observer 켜짐·꺼짐에서는 판단·RNG·예약 순서가 같아야 한다. 큰 사망 사례를 이유로 신규 안전 조건을 추가하지 않는다. V=0, 피해 경계 추가 방식, 가산점 상한 +6, 재배치의 봇 전체 6초 대기, 기존 위험·출발 안전 수치는 보존한다. 순위·점유율 격차는 계속 표시 전용이다.

## 2. 주기·유지 시간 제안

모든 시간은 30Hz 정수 tick으로 정한다. ms는 표시용이다. 다음 값은 3A에서는 사용하지 않고 각 행동 변경 묶음에서 활성화한다.

|항목|제안|적용 조건·이유|
|---|---|---|
|즉시 안전|1tick / 33.3ms|기존 벽 look-ahead, 출발·재배치 시작 검사. 기존 머리 사전 필터 7칸과 1초 겹침 예측 유지|
|전술 안전|3tick / 100ms|노출 선이 있거나 ATTACK/RETURN/ESCAPE/REPOSITION 중에 전체 선 위험·귀환 ETA·역공 검토. 전략이 더 일찍 도래하면 그때도 최신 전술 결과 사용|
|선사냥꾼 전략 주기|5~8tick / 166.7~266.7ms|같은 성격 안에서도 개인별 고정 주기|
|영역탐험가 전략 주기|6~10tick / 200~333.3ms|성장 후보 계산의 분산|
|안전지킴이 전략 주기|4~7tick / 133.3~233.3ms|위험 해소 뒤 확장 재개 기회 유지|
|영역도둑 전략 주기|5~9tick / 166.7~300ms|탈취 기회 확인과 계획 지속의 균형|
|전략 주기 절대 상한|10tick / 333.3ms|500ms에 접근하지 않음. 집요함도 이 상한을 늘리지 않음|
|확장·탈취·점수 확장 최소 유지|18tick / 600ms|유효한 계획의 동급 목표를 자발적으로 갈아타는 경우에만 적용|
|일반 공격 최소 유지|9tick / 300ms|대상·대상 선·접근·귀환이 여전히 유효한 경우에만 적용|
|집요함 유지 배율|×1.5, 올림|확장 27tick / 900ms, 공격 14tick / 466.7ms. 안전·유효성·전술 주기는 그대로|
|귀환 후 재정비|9~24tick / 300~800ms|개인별 고정 길이. 자기 영토 안 경로를 따라 계속 움직이며 다음 출발 경계를 탐색|
|집요함 배정|3C에서 6번째 활성 후보로 추가|성격·닉네임 배정은 유지. 기존 허용 조합 목록에 따라 특성 전용 RNG로 배정|

전술 검사가 필요 없는 자기 땅 안 이동에서는 전략 때 전술 정보를 갱신한다. 첫 외부 칸 출발 검사는 매 tick 유지한다. 기존의 비싼 전체 danger를 매 tick 실행하지 않는다. 출발 검사·전술 검사·전략 판단이 같은 tick에 겹치면 관측과 전술 결과를 그 판단 안에서 한 번 계산해 공유한다. 이전 tick 결과를 경로·생명·소유권 변화 후 재사용하는 캐시는 도입하지 않는다.

## 3. 모듈 계약과 실행 순서

온라인 서버와 LAN은 병합한 `src/shared/room-loop.ts`의 `getBotInputs`를 공통 사용한다. 연습·관전도 같은 디렉터를 유지한다.

|모듈|책임|
|---|---|
|`bot-immediate-safety.ts`|이미 있는 출발 안전·재배치 시작 안전·벽 look-ahead. 기존 조건을 옮기며 새 임계값은 추가하지 않음|
|`bot-plan-validity.ts` (신규 제안)|생명·목표·대상 선·경로·귀환 지점·관측 정보·정체의 유효성. 취소 이유를 하나의 계약으로 반환|
|`bot-tactical.ts` (신규 제안)|기존 danger·귀환 ETA·생존 역공·조기 귀환 판정을 이동. 전략 후보 점수와 구분|
|`bot-strategy.ts` (신규 제안)|기존 확장·공격·탈취 후보와 선택을 이동. 안전 판정을 완화하거나 가산점을 바꾸지 않음|
|`bot-scheduler.ts` (신규 제안)|개인별 전략·전술 기한, 최소 유지, 귀환 재정비 기한|
|`bot-director.ts`|실제 전략 판단 순서와 추격 예약. 즉시 안전을 슬롯 순서 셔플에 묶지 않음|
|`bot.ts`|공개 API를 유지하는 조정자. 기존 테스트와 연습 호출을 보존|

3A는 함수를 분리하되 현재 순서·주기·RNG 호출 위치를 유지한다. **3A가 해시 일치를 통과하기 전 3B 값을 넣지 않는다.**

3B의 tick 처리는 다음 순서로 제안한다.

1. 생명 및 실제 점령·피해 사건을 현재 의미대로 반영한다. 행동 판단을 쉬어도 사건을 놓치지 않는다.
2. 싸고 즉각 확인 가능한 유효성 및 안전을 검사한다. 생명/대상 소멸, 남은 자기 땅 경로 소유권 상실은 유지 시간과 무관하게 처리한다.
3. 전술 도래 시 전체 선 위험·귀환 ETA·역공을 검사한다. 관측 정보 및 시간에 따라 달라지는 유효성도 여기서 갱신한다.
4. ESCAPE·즉각적인 생존 역공·기존 허용된 긴급 공격 전환을 우선한다. 다른 유효 계획의 최소 유지가 이를 막지 않는다.
5. 전략 도래 또는 무효화로 인한 재판단 시 전략 후보를 평가한다. 유효 계획의 동급 자발적 목표 변경만 최소 유지로 제한한다.
6. 최종 선택으로 예약을 반영하고 조향한다. 전략을 건너뛰었다는 이유만으로 ATTACK 예약을 방치하거나 풀지 않는다.

새 안전 예외나 공격 허용 확률을 만들지 않는다. 현재의 `interrupt` 공격 기회는 기존 조건을 통과할 때 전환할 수 있다. 일반적인 안전한 공격을 전부 생존 예외로 예약 상한을 우회하게 만들지 않는다. HOME_CAPTURE는 한 tick의 점령 처리에서 즉시 발생할 수 있으므로 이 구조 분리만으로 사라진다고 약속하지 않는다.

## 4. 시드와 분산·계획 무효화

개인별 주기·시작 위상·재정비 길이는 `botSeed(seed, slot)`에서 분리한 **스케줄 전용 RNG**로 최초 한 번 뽑는다. 구체 도메인은 `0x6c5e9d13`을 제안한다. 행동·성격 셔플·특성·닉네임·예약 순서 RNG를 소비하지 않는다. 봇별 주기에 맞는 시작 위상을 사용하며 `slot % 공통 interval`을 대체한다. 같은 참가자의 부활은 프로필을 유지하고 기한·활성 계획만 새 생명에 맞춰 초기화한다. 참가자 교체는 기존 교체 seed 규칙을 유지한다.

집요함은 전략 주기를 늦추거나 공격 점수·위험 예산을 올리지 않는다. 특성 후보 활성화 자체로 특성 분포와 행동이 바뀌므로 3C를 독립 비교한다.

|무효화 원인|검사·처리 제안|
|---|---|
|자신·대상의 사망/생명 변경/이탈|매 tick 공개 생명 상태 확인, 기존 예약 즉시 해제|
|공격 대상 선 소멸|현재 계획이 겨냥한 관측 가능한 선을 확인. 같은 위치의 새 생명/다른 선에 예약을 붙이지 않음|
|귀환 지점 탈취·자기 땅 경로 상실|공개 owners로 계획의 남은 자기 땅 구간/귀환 지점을 확인. 최소 유지 무시|
|관측 정보 만료|대상이 지역 관측에서 사라지면 원격 머리·선 추적을 계속하지 않음. 현재 시각으로 유효성 재평가|
|진행 불가·정체|현재 코드의 정체 판정 값을 보존. 별도의 더 긴 집요함 정체 시간을 추가하지 않음|
|새로운 치명적 위험·생존 역공|즉시/전술 안전 결과가 계획 유지·귀환 재정비보다 우선|
|귀환 재정비 경로 상실/경로 없음|재정비를 종료하고 현재 규칙으로 재판단. 제자리 대기·영토 밖 강제 이동 금지|

유효성은 체크 빈도만으로 보장되지 않는다. 남은 경로의 어떤 부분을 확인했는지, 정보가 언제 만료됐는지, 전술 스냅샷 tick과 취소 원인을 HUD에 표시한다. 유지 중이란 이유로 무효화 검사를 건너뛰지 않는다.

사망 분류는 `deathContext.cause` 기준이다. EXISTING_TRAIL_CONTACT 78, PENDING_TRAIL_CONTACT 7, HOME_CAPTURE 5는 서로 중복하지 않으며 합계 90이다. WALL_HIT은 0이다. HOME_CAPTURE는 영토 폐쇄 점령으로 선이 끊긴 사망으로, 머리가 기존 선을 직접 밟는 절단과 분리한다. 희소한 5건으로 감소율의 방향 신호를 단정하지 않고 시드·장면별 횟수를 보존한다. 성격별 원인 수·전체 최대 점유율은 증거 JSON, 봇별 회수는 증거 CSV에 저장했다.

기존 audit 되찾기 **3193칸**은 그대로 유지한다. 신규 보조 항목 **1121칸**은 그 생명에서 빼앗겼던 칸을 60초 이내에 중립 상태에서 실제 점령한 횟수다. 점령 transfer를 관측하여 같은 tick에 다시 잃은 획득도 기록하고, 피해 봇 사망 시 기억을 초기화하며 부활 지급 칸은 제외한다. 피해 기억은 audit의 60초 원장으로, AI/HUD의 최대 96칸 기억과 다르다. 기존 되찾기는 tick 경계의 적 소유→내 소유라 같은 tick 일부 전환을 놓칠 수 있어 **두 값의 단순 합을 새로운 총 되찾기라고 부르지 않는다.** 동일 exact-transfer 원장의 적 소유 회수는 진단용 3171칸이다.

## 8. 검증·재검토 기준

- 3A는 8시드 golden 해시·판단·메모리·행동 RNG·예약 순서 일치가 필수다. LAN/온라인 공유 루프도 직접 디렉터 실행과 비교한다.
- 3B~3D는 고정 8시드 같은 조건으로 이전 묶음과 병합 기준을 각각 비교한다. 보유 시간 평균이 주 성장 지표이며 최종 보유·최대 점유율, 사망 원인별 수, 기존 되찾기·중립화 피해 회수, 성격별 탈취 비중·TV, 계획 교체·무효화 이유·공격 기회, 비용을 보고한다.
- 보유 시간 평균 −5%, 사망 또는 비용 +20%를 넘으면 기존 재검토 절차를 적용한다. 개선/악화/동률 시드 수와 leave-one-out 방향을 함께 쓴다. 7/8 같은 방향 및 모든 leave-one-out 방향 유지가 방향 신호다. 그 밖은 구분 불가이며 효과 없음·동등이라고 쓰지 않는다.
- 벽 사망 0, 계획 추격 예약 최대 3, 관측 밖 머리·선·방향 사용 금지, HUD 비간섭 조건을 유지한다. 기존 생존 역공 예외와 예약 통계는 분리한다.
- 무효 계획에 집요함이 적용되지 않는 테스트, 전략을 쉬는 tick의 즉시 안전 및 전술 귀환, ATTACK 예약 갱신·해제, 서로 다른 주기의 분산·재현성, 재정비 중 자기 땅 경로 상실과 대기/외부 이동 방지 검증을 추가한다.
- 성능은 원본 trace/벽 회피·피해 원장 observer 없이 같은 세션·순서 교차 반복으로 측정한다. 동일 경로 plannedCapture 캐시는 계속 보류한다.
- 각 행동 변경 묶음의 자동 검증 이후 사용자 관전으로 계획 이유·유지·취소가 자연스러운지 확인한다. 3단계 승인 전에는 구조 분리 코드도 넣지 않는다.
