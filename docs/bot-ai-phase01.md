# 봇 AI 0+1단계 구현 — 2026-10-09

브랜치: codex/bot-ai-phase01. 시작점은 당시 origin/master와 같은 깨끗한 master다. 기존 참가자 14명 설정과 안전 리스폰은 유지했다.

## 구현 범위

- 실제 봇 수에 따른 균등 성격 배분과 시드 셔플. 새 참가자 투입은 부족한 성격 우선; 부활 시 기존 memory의 성격·특성을 유지한다.
- 성격별 개인차와 6개 2차 특성. Coward/Gambler/Opportunist/Territorial은 가중치로 작동한다. 자동 배정은 이 4개만 사용한다. Vengeful/Persistent는 정의와 명시적 실험 배정만 유지하고, 효과를 켜는 단계에서 자동 배정 후보에 추가한다.
- 48개 시작 닉네임. 사람·봇 전체 참가자와 정규화한 이름 중복을 피하고, 목록 소진 시 중복 없는 대체 이름을 만든다. 200–300개 콘텐츠 검토는 마지막 단계다.
- 연습 + development/test + debug=1에서만 HUD를 켠다. 슬롯, 성격, 특성 활성 여부, 상태, 대상, 선 길이, 판단 시점 위험, 실제 선택·거절·안전 개입 사유, 최근 8개 전환을 표시한다.
- 개발 플래그에서만 사람 없이 14봇이 진행하는 관전 세션을 제공한다. 선택 봇 따라보기 / 전체 판 보기로 카메라를 전환하며 입력과 사람 보상은 비활성화한다. 일반 연습의 1인+13봇과 사람 사망 시 정지는 유지한다.
- 최근 판단과 현재 계획을 만든 판단을 따로 기록한다. 새 확장·공격·귀환 경로, 목표 전환과 안전 개입 때 갱신하며, waypoint 진행이나 PLAN_CONTINUE는 계획 기록을 덮지 않는다. 같은 EXPAND 목표에서 새 계획을 선택하는 경우도 갱신한다.
- HUD는 기존 판단에서 계산한 후보만 기록한다. 별도 shadow 탐색을 실행하지 않는다. CLI audit의 기존 shadow 계측은 유지한다. HUD의 clearDecisionCount는 미평가를 뜻하는 null이다.

원한 유지, 추격 예약, 3층 판단, 성장 정체 대응, 1위 견제는 이번 구현에 포함하지 않았다.

## 1단계 초기 튜닝값

아래 범위는 개인차와 특성을 합산한 최종 범위다. riskScale이 클수록 더 조심하며, 위험감수 확률을 뜻하지 않는다. 공격 값은 기존 attack 평가 계수이며 최종 공격 선택 빈도와 같지 않다.

| 성격 | 확장 배율 | 위험 가중 배율 | 탈취 가중 배율 | 공격 계수 | 침입 방어 점수 |
| --- | --- | --- | --- | --- | --- |
| Explorer | 0.85–1.30 | 0.80–1.25 | 0.70–1.30 | 0.04–0.18 | 0–6 |
| Hunter | 0.80–1.20 | 0.75–1.25 | 0.70–1.30 | 0.80–1.00 | 0–6 |
| Guardian | 0.80–1.15 | 0.90–1.30 | 0.70–1.20 | 0.01–0.06 | 12–18 |
| Thief | 0.85–1.20 | 0.80–1.20 | 0.85–1.30 | 0.12–0.30 | 0–6 |

- Coward: 확장 ×0.90, 위험 가중 ×1.15, 공격 ×0.80.
- Gambler: 확장 ×1.15, 위험 가중 ×0.85, 공격 ×1.10. Guardian 조합은 금지한다.
- Opportunist: 공격 +0.05, 탈취 ×1.15.
- Territorial: 자기 영토 또는 바로 인접한 선 침입에 방어 +6. Guardian의 기본 +12를 유지한다. 무관한 상대에는 추가 점수를 주지 않는다.
- Vengeful/Persistent: 이번 단계 효과와 자동 배정 없음. 명시적 회귀 fixture에서는 사용할 수 있다.

성격 셔플, 개인차, 특성, 닉네임은 별도 RNG 스트림이다. 이름 목록·HUD 유무는 성격 및 행동 RNG를 바꾸지 않는다. 슬롯별 성격은 botSpecs의 overrides, 특성은 createBotIdentity의 secondaryTrait, 연습 통합 테스트는 PracticeSession의 botOverrides로 지정한다. 기존 회귀 witness는 tests/bot-fixtures.ts의 명시적 슬롯 배정으로 보존하며, 새 운영 배정은 별도 테스트한다.

## 관전 방법

1. npm run dev:client 실행.
2. http://127.0.0.1:5173/?debug=1&spectate=1&experimentSeed=19 에서 싱글 플레이 시작. 사람 없이 14봇 관전 세션이 열린다. 일반 debug 연습에서는 HUD의 **14봇 관전 시작** 버튼으로 전환할 수 있다.
3. 오른쪽 HUD의 봇 행을 선택해 상세 판단을 확인한다. 선택 봇 따라보기 / 전체 판 보기 버튼으로 카메라를 전환한다.
4. 최근 판단에는 PLAN_CONTINUE와 현재 위험이 표시된다. 현재 계획을 세운 판단에는 원래 선택 이유, 그때 공격 후보·거절 사유, 확장 상위 후보·거절 집계가 유지된다. 부활 시 이전 생명의 계획 기록은 재사용하지 않는다.
5. 접기 버튼으로 화면 공간을 확보한다. 경기 메뉴·종료 확인은 HUD보다 위에 표시한다. 게임을 나가면 HUD와 관측 콜백을 해제한다.

시드 19는 재현 가능한 배정 예시다. 일반 게임은 새 시드로 배정한다. 일반 연습 모드의 사람 사망 후 일시 중단은 유지한다. debug=1 없이 또는 운영 빌드에서는 spectate=1을 주어도 일반 연습을 시작한다. 관전은 기존 Classic 시뮬레이션을 그대로 사용한다.

사망 감사는 Classic R22, 총 14명, 8시드 × 순수 봇/2인 혼합의 16경기다. 기존 audit는 패딩 적용 전 벽 경계를 검사해 양쪽 모두 동일한 HUMAN 벽 오탐 7건을 냈다. 실제 boundaryGeometry로 검사만 정정했으며 이동·사망 규칙은 변경하지 않았다. medium-attack 감사는 원래 회귀용 R22/19칸 스폰 전제를 명시해서 양쪽 동일하게 비교한다.

자동 체크와 성능 수치는 최종 결과 절에 기록한다. 사용자의 관전 판단 후 2단계 진행 여부를 정한다.

## 관전 검토 후 수정

1·2·3·6번을 반영했다. 서버 초기 memory와 loop 예비 memory는 공유 botSeed(seed, slot)을 사용한다. 참가자 교체 시 추가하는 tick 시드도 유지한다.

특성 배정 후보가 달라져 같은 시드의 특성과 행동도 바뀐다. 위 성능·성장 감사 수치는 4d07624 당시 결과이며 이번 수정의 측정값이 아니다. 4번 범위 절단 튜닝과 5번 성장 지표 추가는 이번 수정에 포함하지 않았다. 성장 지표는 4단계 전에 추가해야 한다.

최종 수정 검증:

- 타입 검사·운영 빌드 통과. 기존 번들 크기 경고만 남았다.
- 전체 회귀: 81파일 491개 통과 (`npm test -- --maxWorkers=2`). 기본 병렬 실행은 브라우저 검증과 동시에 진행해 CPU 부하로 2건이 시간 초과됐고, worker 제한 재실행에서 모두 통과했다.
- 브라우저 3개 통과: 일반 연습 1+13, 사람 없는 관전 14봇의 1,800틱 진행·사망 이후 지속·일시정지·카메라 중심, 전환·종료, 개발 플래그 없는 환경과 운영 빌드 제외.
- 활성 특성 분포, 같은 목표의 새 계획, waypoint 진행 중 원인 보존, 새 생명 기록 무효화, 판단 주기 사이 벽 회피 및 반복 회피, 서버 예비 memory 시드 정합성을 확인했다.
- R22/R56에서 HUD 유무에 따른 입력·시뮬레이션·다음 RNG 값의 일치를 확인했다. HUD는 추가 후보 탐색을 실행하지 않는다.
- PC에서 선택 봇을 HUD가 가리지 않도록 너비를 조정했다. 현재 화면 증거는 evidence/bot-phase01/hud.png 및 spectator.png, 검증 요약은 review-fixes.json이다.
