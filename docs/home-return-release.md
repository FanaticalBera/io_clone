# 복귀 여유 10단위 정식 채택 — 2026-10-15

사용자는 별도 S24+ 복귀테스트 앱에서 10단위가 적당하다고 평가하고 이 값의 일반 적용과 master 병합을 승인했다. 6/10 비교 이력은 `docs/home-return-margin-experiment.md`에 보존한다.

## 최종 동작

- 일반 싱글·LAN의 공통 엔진에서 사람과 봇 모두 같은 복귀 여유를 사용한다. side 32에서 10 world units이며 다른 side에서는 10/32 비율로 유지한다. 경계에 수직 접근할 때 약 40.9ms, 줌 .38에서 약 3.8 CSS px의 여유다.
- 열린 꼬리가 자기 땅 여유 범위 밖에서 다시 안으로 들어올 때 조기 복귀한다. 출발 직후·밴드 내부의 평행 이동·한 칸 중립 틈 통과에 대한 제한과 기존 중심 진입 복귀를 유지한다. 상대 꼬리 직접 절단 범위는 바꾸지 않았다.
- 앞선 LAN 수정도 포함한다. 점령 완료로 꼬리가 회수되면 다음 정기 10Hz 갱신까지 기다리지 않고 같은 scheduler pass에 reliable 스냅샷을 보낸다. 탈락 즉시 전달과 중복 방지도 유지한다.
- 마커·주변 원·펄스·UI·봇 정책·부활 정책·가격은 이번 채택에서 변경하지 않았다. 공통 물리 규칙이 바뀌므로 봇의 점령 시점과 실제 경기 결과는 달라질 수 있다.
- 일반 앱에는 별도 테스트 앱의 진단 전역 API·카운터·홈 버튼 문구나 플레이어 무적 기능을 넣지 않았다.
- 클로드의 맵 master `573b93e`는 이미 프로토콜 8이어서 최종 통합본을 **`PROTOCOL_VERSION` 9**로 정리했다. 방장과 게스트 모두 같은 최종 앱 버전으로 갱신해야 한다. 구버전 연결 거부는 기존 버전 검사 경로를 사용한다.

## 검증

- 최신 맵 통합 후 전체 112파일: **1,092개 통과 + 기존 예상 실패 8개**(총 1,100). 이후 추가한 LAN 맵 선택 6건도 별도 통과하여 현재 테스트 총수는 1,106이다. client/server/tests 타입 검사, 통합 웹·서버·일반 Android debug APK 빌드 통과.
- 정상 PracticeSession의 기본값 10, HUMAN/BOT 공통 기본값, LAN 방장·게스트 각각의 조기 복귀와 양쪽 클라이언트 수신을 검사했다. 실험 setter 없이 중심이 아직 원래 집 밖인 장면에서 실제 점령을 확인한다.
- 6/10 기하 비교, 모서리·출발·평행 이동·틈·적 영토·절단 선후 및 상대 꼬리 범위를 검사했다. 기존 R22/4.2 속도의 과거 회귀 도우미와 중심 진입 비교 테스트는 명시적인 0단위 기준으로 보존한다. 전체가 현행 10단위 조건이라는 뜻은 아니다.
- 실험 setter 없이 정식 기본값으로 실행한 14봇, seed 4·137 각 90초: 점령 503·455회, 조기 복귀 472·433회, 사망 7·4회. 주기적 소유권 수·생존 상대 꼬리 접촉 검사 및 엔진 반복 처리에 오류가 없었다.
- 최종 기본값의 인간 1+봇 13 LAN 호스트 60초: 스냅샷 790회(평균 13.17Hz), loopback 포함 직렬화 38,101,310바이트, 오류 0. 앞서 0단위에서 즉시 점령 전달만 켠 비교값은 772회였으며 물리 규칙 변화로 경기 이벤트 수는 달라졌다. 실제 외부 무선 전송량이나 장시간 발열 측정값은 아니다.
- 클로드의 최신 맵 master `573b93e`를 먼저 작업 브랜치에 병합한 뒤(`7390c04`) 내 미커밋 변경을 복원했다. 충돌은 `config.ts`의 버전 주석 구간이었으며 `mapShape` 필드·검증은 모두 보존하고 버전을 9로 정리했다. `src/shared/rooms.ts`·맵 UI·마커 표현은 최신 맵 master와 동일하게 유지했다.
- 육각·직사각·섬·도넛·십자·꼬마 육각 6종에서 실제 맵 가장자리 칸의 10단위 조기 복귀와 소유권/형태 wire 왕복을 확인했다. 방장의 6종 맵 선택·게스트 권한 제한·양쪽 LAN 클라이언트의 형태 및 정원 수신도 검사했다. 맵 통합 전의 검사 결과와 구분하여 전체를 재실행했다.
