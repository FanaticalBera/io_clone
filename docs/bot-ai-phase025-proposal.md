# 봇 AI 2.5단계 초기값 제안

작성: 2026-10-10. 상태: **승인됨 / 묶음 ①·② 구현·자동 검증 완료 / 사망 증가 재검토 필요 / ③ 관전 후 결정**.

비교 기준은 `0384f9a`, 구현 출발점은 원한 원인 HUD가 추가된 `8485fe2`다. 3단계의 판단 주기·3층 분리 전에 반복 피해 대응을 별도 구현한다. 아래 수치는 사용자가 승인했다. 우선 ① 피해 기록·누적·HUD와 ② 피해 대응 경계·가산점을 적용하고 보고한다. 사용자 관전 후 먼 피해 구역에 닿지 못하는 장면이 남을 때만 ③ REPOSITION을 진행한다. 기존 2단계 값은 [승인값 기록](bot-ai-phase02-proposal.md), 기존 검증과 관전 피드백은 [2단계 결과](bot-ai-phase02.md)를 따른다.

## 목표와 범위

반복해서 영토를 뜯긴 봇이 피해를 기억하고 안전한 되찾기·복수 탈취를 선택하도록 한다. 먼 피해 구역에 접근할 수 있도록 `REPOSITION`을 추가한다. 모든 성격을 추격자나 영역도둑으로 바꾸지 않는다.

변경 범위는 공개 소유권 변화 기반의 피해 집계, 피해 구역 기억, 재배치, 확장 후보의 대응 가산점, 진단이다. 이동 물리·속도·점령·사망·리스폰 규칙, 성격/특성 배정 RNG, 일반 판단 주기 200ms, anti-dogpile과 공격 안전 기준은 유지한다. 공격 거절 사유·움직임 유사도는 측정·보고만 한다. 일반 계획 유지·3층 판단은 3단계, 성격 범위에 잘리는 특성 효과는 후속 튜닝이다.

원한 상한 20, 사망 +5, 감쇠 45초/복수심 90초, 공격 `valuable >= 6`, 원한 공격 가산·복수심 배율·접근/침입 규칙은 유지한다. 두 번의 +3도 그 사이 감쇠하면 6 미만이 될 수 있다. 아래 복수 탈취 가산은 6을 필수 조건으로 삼지 않고 현재 원한에 연속적으로 비례한다.

### 공개 소유권 사건의 경계

엔진이 실제 소유권을 이전하기 전의 `winners`와 이전 `owners`에서, 살아 있는 피해자의 소유 → 다른 참가자의 소유로 바뀐 칸을 기록한다. 현재 `observedCaptureLosses`의 거리 조건으로 버리지 않고 **전체 피해 칸과 당시 피해자 주변 12칸 안의 피해 칸을 구분**한다. 전체 피해·위치·당시 가해자 ID는 원한/피해 구역에, 근처 피해 수만 기존 pressure에 전달한다. 관측 밖 손실 때문에 pressure까지 자동으로 확대하지 않는다.

`recordBotCapture` 경로를 확장하며 피해 칸 ID가 추가로 필요하다. 사건은 칸별 소유권 이전이 발생한 시점의 가해자에 귀속한다. A→B→C이면 A의 최초 피해는 B에게 귀속하고, 나중의 현재 주인 C로 바꾸지 않는다. 주인 없는 칸 점령·사망 중립화·리스폰 지급·단절 영토 정리로 중립화된 칸은 탈취 원한으로 만들지 않는다. 실제 점령된 연결부 때문에 발생한 사망은 기존 처치 귀속을 보존한다.

미니맵은 전역 영토 색을 표시한다(`game-scene.ts`의 미니맵 렌더링); 봇도 전체 `owners`를 사용한다. 이 공개 정보로 피해를 귀속하는 것과 관측 밖 상대의 머리·선·방향을 읽는 것은 구분한다. 사건 payload에는 상대 머리 위치·선·방향·입력 의도를 넣지 않는다. 로컬/원격 표시는 피해 칸 거리 기준이며 가해자 머리를 봤다는 뜻이 아니다.

제3자가 가져간 피해 칸은 최초 피해 가해자 기억을 변경하지 않는다. 되찾기 가산은 예전 내 땅인 위치에 적용할 수 있지만, 복수 가산은 **후보 평가 시 실제로 해당 가해자가 소유한 칸**에만 적용한다.

## 3. 현재 위치에서의 후보와 가산점

가산점은 기존 안전 검사를 통과한 확장 후보에만 계산한다. 공격 후보에는 이 가산점을 더하지 않는다. 같은 칸이 되찾기 D와 복수 V에 동시에 들어가는 것은 의도된 동작이며 두 항목을 합산한 뒤 기존 +6/기본 점수 50% 상한을 적용한다. `plannedCapture`가 이미 계산한 예상 점령 칸을 재사용하며 추가 행동 RNG를 뽑지 않는다.

| 항목 | 제안 초기값·규칙 | 이유 |
| --- | --- | --- |
| 경계 후보 총수 | 기존과 같은 최대 6개 | 후보 생성량을 제한한다. |
| 피해 대응 경계 배정 | 가까운 일반 경계 4개 + 피해 대응 경계 최대 2개 | 피해 쪽이 가까운 6개 밖에 있어도 후보에 들어올 수 있게 한다. |
| 빈 슬롯·중복 | 나머지 가까운 경계로 채움; 같은 경계는 한 번 | 피해 구역이 없으면 기존 6개 순서와 생성 방식으로 돌아간다. |
| 대응 경계 조건 | 기억된 피해 칸에서 hex 거리 3 이내인 자기 영토 경계 | 단순히 적 영토 전반을 찾아가지 않는다. |
| 직접 확장 접근 경로 | 기존 자기 영토 내부 최대 10칸 | 24칸 전체 확장 한도를 유지한다. 더 먼 곳은 다음 절의 별도 이동으로 접근한다. |
| 가산 평가 정보 범위 | 현재 머리 주변 12칸 안의 예상 점령 칸 | 먼 상대 영토의 소유 정보를 따라 원정하는 가산을 만들지 않는다. 실제 기본 점령 계산은 기존과 같다. |
| 되찾기 단위 가산 | 피해 기억 무게가 반영된 예상 되찾기 1칸당 +0.50 | 출발점만 가깝고 반대 방향으로 뻗는 계획에는 붙지 않는다. |
| 되찾기 유효 칸 상한 | 가중 합계 6칸 | 큰 피해 구역 하나가 무제한 보너스를 주지 않는다. |
| 복수 단위 가산 | 가해자 소유 예상 점령 1칸당 +0.75 × (현재 원한/20) | 원한 3·5도 작은 행동 차이를 만들고 높은 원한일수록 강해진다. |
| 복수 유효 칸 상한 | 가해자별 가중치를 합친 뒤 총 6칸 상당 | 여러 원한 상대가 있어도 보너스가 무한히 합산되지 않는다. |
| 영토집착 | 되찾기 항목 ×1.50 | 피해 구역 대응을 강화한다. 기존 방어 공격 보너스는 유지한다. |
| 복수심 | 복수 탈취 항목 ×1.50 | 기존 복수심 공격 점수 배율과 별개인 확장 효과다. 사건 적립량은 늘리지 않는다. |
| 합계 절대 상한 | +6점 | 탈취 보너스 중첩을 제한한다. |
| 합계 상대 상한 | 기본 후보 점수의 50%, 음수는 0으로 취급 | 기본 평가가 나쁜 후보를 보너스로 살려내지 않는다. |
| 최소 보장 가산 | 없음 | 안전지킴이 반응이 약하면 후속 관전 튜닝으로 별도 제안한다. |

계산 정의:

- `D = min(6, Σ 예상 점령 칸 중 기억된 피해 칸의 현재 무게)`; 한 칸을 여러 원인으로 중복 합산하지 않는다.
- `V = min(6, Σ 예상 점령 칸이 현재 원한 상대 소유이면 해당 상대의 grudge/20)`.
- `raw = 0.50 × D × 영토집착배율 + 0.75 × V × 복수심배율`.
- `bonus = min(raw, 6, 0.50 × max(0, baseScore))`.
- `finalScore = baseScore + bonus`.

`baseScore`는 이번 2.5 가산을 넣기 전의 기존 완성된 확장 점수다. 점령량·기존 탈취 가중치뿐 아니라 경로 비용·위험·회전·반복 패널티·기존 RNG 미세 보정까지 포함한다. 안전 판정이 끝난 뒤 위 가산을 적용한다. 성격별 루프 크기·선 길이·공격 우선 개입은 보존한다. 유효 칸은 실제 되찾는 칸으로 좁혀 시작하며, 피해 칸 근처에만 새 땅을 먹는 별도 보너스는 처음에는 추가하지 않는다. 경계 접근 편향은 후보 배정과 `REPOSITION`으로 표현한다.

예: 기본 점수 8점이면 최대 가산은 4점이다. 기본 점수 2점이면 최대 1점이고, 0 이하이면 가산은 없다. 따라서 작은 안전 루프의 반응이 약할 수 있다. 상대적으로 먼 곳을 무조건 되찾도록 만드는 값이 아니며 자연 관전·반복 피해 fixture로 효과를 확인한다.

## 4. REPOSITION: 자기 영토 내부 재배치 (③ 보류 설계)

기존 확장 계획에 긴 내부 접근 경로를 붙이지 않는다. 자기 영토 내부 이동을 별도 `REPOSITION` 계획으로 실행하고, 피해 쪽 경계에 도착하면 현재 관측으로 평소 확장 후보를 다시 생성한다. 확장 전체 24칸 제한과 외부 선 한도를 유지한다. 사전에 만든 오래된 루프를 도착 뒤 이어 붙이지 않는다.

| 항목 | 제안 초기값·규칙 | 이유 |
| --- | --- | --- |
| 진입 시점 | 새 확장 계획을 만드는 시점, 자기 영토 안·노출 선 0 | 실행 중 공격·탈출·귀환을 재배치 때문에 중단하지 않는다. |
| 피해 활성 조건 | 해당 상대의 최근 10초 실제 피해 6칸 이상 또는 원한 6 이상, 유효 피해 구역도 존재 | 대기 중 피해도 실제 피해/구역에는 남는다. 원한만 있고 구역이 없으면 원정하지 않는다. |
| 목적지 | 기억된 피해 칸에서 3칸 이내의 현재 자기 영토 경계 | 상대의 숨은 머리가 아니라 과거 자기 영토 위치로 이동한다. |
| 경로 조건 | 남은 모든 칸이 현재 자기 소유인 경로 | 경유 때문에 외부 선을 만들지 않는다. |
| 재배치 거리 | 내부 경로 11–20칸 | 10칸 이내는 앞 절의 대응 경계를 일반 확장 후보로 평가한다. |
| 목적지 탐색 상한 | 최대 8개 경계의 내부 경로 확인 | 최근·가중 피해 구역에서 뽑아 탐색량을 제한한다. 동률은 cell ID로 고정한다. |
| 목적지 우선도 | `P = min(6, 구역 유효 기억 무게 합) × 영토집착배율 + 2 × grudge/20 × 복수심배율 − 0.20 × 내부 경로 칸 수` | 오래되고 작은 피해에 대한 긴 이동은 덜 선호한다. 같은 구역을 여러 경계에서 중복 합산하지 않는다. |
| 선택 조건 | 도달 가능한 후보 중 P > 0, 최대 P → 짧은 경로 → cell ID | 별도 추첨 RNG 없이 결정한다. |
| 유효 구역 범위 | 목적지 3칸 이내의 기억된 피해 칸 | 관계없는 먼 피해 구역을 더해 목적지 점수를 올리지 않는다. |
| 도착 | 실제 cell ID가 목적지와 같고 자기 소유이며 노출 선 0 | 순간 이동·화면 보정 없이 도착한 뒤 새 계획을 만든다. |
| 최대 이동 시간 | 8초 | 기본 속도 4.2칸/초에서 20칸 접근과 회전 여유를 포함한다. 오래된 목적지에 붙잡히지 않는다. |
| 재시도 대기 | 성공·중단 후 봇 전체의 재배치 6초 대기 | 두 가해자가 반대쪽에서 뜯어도 상대를 바꿔 대기를 우회할 수 없다. 같은 목표 재선택·왕복 반복을 줄인다. 피해·원한 기록은 계속한다. |
| 위치·구역 무효화 | 남은 경로 중 하나라도 자기 소유가 아니거나, 도착 경계가 아니게 되거나, 목적지 주변 유효 피해 칸이 0개면 중단 | 현재 코드의 마지막 귀환 칸 검사만으로는 내부 경로 탈취를 못 막는다. |
| 생명·상대 무효화 | 자기 사망/생명 교체, 해당 가해자 ID 이탈 | 원한을 새 ID에 넘기거나 옛 영토로 이동하지 않는다. |
| 기존 위험 | 노출 선이 예기치 않게 생기거나 기존 danger가 켜지면 중단·기존 안전 대응 | 실제 이동 실패·소유권 변경에도 기존 탈출 처리를 우선한다. |
| 내부 이동의 추가 근접 조건 | 관측된 상대 머리가 현재 칸 또는 다음 3개 경유 칸에서 2칸 이내면 중단 | 기존 danger는 내 선이 있어야 켜진다. 선 없는 내부 이동의 보수적 재평가 조건을 명시한다. 새 공격 안전 기준으로 사용하지 않는다. |
| 검사·재평가 | 경로 소유권·근접·생명 조건은 매 tick, 구역 만료·시간 제한은 기존 판단 시점 | 즉시 중단 시 지역 관측을 다시 만들어 기존 정책으로 재평가한다. 상대 정보 범위는 12칸을 넘기지 않는다. |

일반 판단 주기는 바꾸지 않는다. 도착·소유권 무효화·즉시 위험은 이 상태의 사건성 재평가 예외로 처리한다. 위험이 해소됐다고 같은 프레임에 재배치를 다시 시작하지 않는다. `REPOSITION` 자체는 ATTACK 추격 예약을 잡지 않는다. 기존 정책에서 유효한 공격 개입이 발생하면 기존 안전 검사·디렉터 예약 규칙으로 전환하며, 재배치를 핑계로 새로운 공격 허용 조건을 만들지 않는다.

REPOSITION의 근접 검사는 조건 발견 전부터 다음 3개 경유 칸을 검사할 수 있는 지역 머리 관측을 제공해야 한다. 기존 light 관측의 가장 가까운 머리 1개만 재사용하면 경로 앞쪽 위협을 놓칠 수 있다. 필요한 관측은 현재 머리 주변 12칸 안으로 제한하며, 관측 밖 머리·선·방향을 읽지 않는다. 검사 비용은 성능 비교에 포함한다.

보통 선이 없어 기존 `danger`가 false인 점을 테스트한다. 내부 이동을 무위험으로 가정하지 않는다. 도중 영토가 빼앗기면 실제 이동 전에 남은 경로를 무효화한다. 머리가 이미 외부로 밀려났거나 선이 생겼다면 기존 RETURN/ESCAPE 처리를 우선한다. 20칸 밖 피해 구역에는 이번 상한으로 접근하지 못하며 HUD에 거리/도달 불가를 표시한다.

새 상태의 색·상태 전환 기록·현재 목적지·중단 사유를 HUD와 audit에 연결한다. Look-ahead는 기존 이동/귀환의 공통 근접·벽 보정 방식을 유지하고 이동 물리를 수정하지 않는다.

## 5. 보고만 하는 측정 범위

공격 후보를 성격별로 `관측된 후보 없음 / 안전·경로 검사 탈락 / 선택 가능한 후보가 다른 계획에 밀림 / 실제 공격 선택`으로 구분한다. NO_APPROACH, VICTIM_RETURNS_FIRST, TRAIL_BUDGET, COUNTER_CUT_FIRST, LOW_PRIORITY, UNSAFE_RETURN, 예약 제한을 각각 집계한다. 최신 판단과 계획 생성, 잠긴 공격 유지와 새 공격, 반복 후보 검사·공격 에피소드를 구분하고 분모를 명시한다. 무조건 가장 많은 거절 사유가 잘못된 조건이라고 결론내리지 않는다.

성격별 목표 점유 시간, 확장 모양·크기, 탈취 칸 비중, 근접 조건에서의 작은 루프 비율을 보고한다. 현재 공통 근접 안전 루프·공격 확률·거절 조건·특성 범위 절단은 이번 측정 결과를 근거로 별도 제안하며 2.5 구현 중 함께 조정하지 않는다.

## 6. HUD와 결과 지표

기존 상대 번호·닉네임, 원한 원인·경과 시간·생명 번호를 유지한다. 누적 피해/6칸, 재적립 대기와 미적립 사유, 전체 피해/근처 피해/미니맵 피해를 추가한다. 피해 구역 기억 무게와 최근 위치, 선택 계획의 baseScore·되찾기·복수 raw·상한 적용 뒤 가산점, 후보 거절, 재배치 목적지·내부 거리·도착/중단 사유를 표시한다.

왕복 반복은 단순히 같은 가해자 재선택만 세지 않는다. ③ 진행 시 같은 생명의 봇이 두 가해자에 대응하여 A→B→A로 재배치하는 장면을 기록한다. 30초 안의 세 목적지, 반대 방향(이동 방향 각도 120도 이상), 각 이동에서 실제 내부 경유 2칸 이상을 함께 확인하며(성공/중단 모두 포함, 가해자는 참가자 ID로 구분하고 방향은 실제 시작·종료 위치의 변위로 계산), 미실행 계획 교체와 실제 왕복을 분리한다. 현재 ①·② 결과에서 재배치 횟수를 관측했다고 주장하지 않는다.

원한 사건과 피해 구역 기록은 분리한다. 재적립 대기 중인 실제 피해도 구역에는 남고 HUD에서 보이며, 그 사건으로 원한 적립이 없음을 명시한다. 사망으로 땅이 중립화되거나 제3자에게 넘어간 칸의 현재 주인으로 최초 가해자를 덮어쓰지 않는다.

최종 평가는 기존 순영토 증가·총 점령·사망·최대 점유율·확장 취소/조기 귀환에 더해, 성격별 탈취 비중·실제 되찾은 칸/횟수·가해자 영토 탈취 칸·대응까지 시간·재배치 성공/중단/왕복 반복을 포함한다. 단순히 대응 보너스가 붙은 후보 수를 실제 대응 성공으로 세지 않는다.

## 7. 검증 및 비교 조건

①·②의 실행 결과는 [구현·검증 결과](bot-ai-phase025.md)에 기록한다. 아래 검증 계획 중 ③ 관련 항목은 사용자 관전 후 진행을 허용할 때 실행하며 현재 완료로 주장하지 않는다.

1. 실제 이동으로 B가 A에게 6칸 미만 피해를 반복해서 주는 fixture: 창 안에서 합계 6칸이면 +3, 적립 시 전부 소비, 2초 대기 중 피해는 누적에서 제외하되 구역/HUD에 남음, 10초 만료·중복·18칸 단일 사건·자기 사망 경계를 검증한다.
2. 실제 소유권 이전 A→B→C, 같은 tick의 여러 점령, 중립화·단절 정리·리스폰 지급: 피해자의 원한이 당시 실제 가해자에게만 귀속되는지 확인한다. 피해 칸이 머리에서 멀어도 전역 공개 소유권으로 기록되고, pressure는 근처 칸만으로 계산되는지 확인한다.
3. 동일 공개 소유권·피해 기억에서 관측 밖 상대의 머리·선·방향·입력만 바꿔도 판단·RNG가 같아야 한다. 공개 소유권 변화가 다르면 같은 판단을 요구하지 않는다.
4. 실제 이동의 안전한 반복 탈취에서, A가 피해 방향의 확장이나 REPOSITION 후 안전한 되찾기를 선택하고 실제 점령까지 하는지 확인한다. 안전하지 않은 상대 선·머리·귀환·선 한도 상황에서는 가산점이 있어도 기존 안전 처리가 우선해야 한다.
5. **③ 보류 항목:** 10/11/20/21칸 접근 경계, 도중 경로 탈취, 목적지 변경·피해 구역 소멸, 선 없는 근접 중단, 8초 제한·6초 재시도 대기, 자기 부활을 확인한다. 이동 후 루프가 기존 24칸·성격 크기 제한을 지키는지 확인한다.
6. Guardian의 작은 루프, Hunter의 유효한 공격, Explorer의 성장, Thief의 탈취가 남는지 확인한다. 후보 수·기억 한도·결정적 순서·기본 점수 0/음수·절대/상대 상한·중첩 가산을 검증한다.
7. HUD 수집·표시 켬/끔에서 실제 입력·게임 상태·감정/구역 기억·행동 RNG·디렉터 예약 순서가 같다. 새 REPOSITION은 예약을 쓰지 않으며 기존 예약 상한/생존 예외가 유지된다. 정상판·배포 빌드의 HUD 비노출을 확인한다.
8. 0384f9a와 동일한 R56/스폰 7칸/14 BOT/안전 부활/동일 배정·행동 시드·클래식에서 시드 4·19·73 각 120초를 비교한다. 8485fe2의 진단을 버리거나 기존 커밋의 게임 동작을 변경하지 않는다. 기존 밀집 사망/중거리 공격 fixture도 보존한다.
9. 가능하면 ①전역 피해·누적 ②피해 구역 가산 ③재배치의 중간 결과를 같은 조건으로 남겨 효과를 분리한다. 코드 스위치가 필요하면 실험/테스트 전용으로 두며 일반 게임 UI에 내부 설정을 노출하지 않는다.

성장·사망·비용의 비율은 사용자가 승인한 재검토 기준이다. 기준을 통과해도 관전 재미가 보장됐다고 결론내리지 않는다. 반대로 자연 대전에서 REPOSITION이나 원한 20이 적다는 이유만으로 필수 fixture를 생략하지 않는다.

## 8. 구현 분리와 작업량 판단

첫 묶음은 엔진 공개 소유권 손실 기록·혼합 로컬/원격 칸·누적/중복/대기·HUD다. 둘째는 피해 구역의 경계 후보와 제한된 가산점, 셋째는 REPOSITION의 진입·도착·즉시 무효화·디렉터/관측 경로·HUD·실제 이동 테스트다. 중간 비교 결과를 남기되 사용자에게 미검증 중간 상태를 완료라고 보고하지 않는다.

이는 숫자 몇 개만 조절하는 작은 패치가 아니다. 현재 LOSS는 칸 수만 넘기며 위치가 없고, danger는 내 선이 있어야 켜지고, 경로 무효화도 마지막 귀환 칸만 본다. ③ 진행 시 새 상태는 판정 경로·관측의 light/full 경로·디렉터 due 처리·콜렉터·HUD·audit·실제 이동 검증에 걸친다. 필요한 범위의 상태 무효화만 먼저 구현하며 3단계 전체 리팩터링을 섞지 않는다.

사용자는 수치와 설계를 승인했고, ①·②를 먼저 구현·자동 검증·보고하도록 범위를 정했다. ③은 이 문서의 설계를 보존하며 사용자 관전에서 먼 피해 구역 때문에 대응하지 못하는 장면이 실제로 남을 때만 진행한다. ①·② 완료를 ③ 또는 3단계 착수 승인으로 해석하지 않는다.
